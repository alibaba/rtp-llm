FlexLB 目标类图：成员与接口

设计日期：2026-11-02，修订 2：移除独立 SchedulerLoop，调度模块自行管理触发。目标设计，尚未实施；本图不描述当前运行代码。

64 个顶层类型，8 个分区，预算合计 18,580 行有效代码。 单类 ≤1,000，方法/构造器 ≤50，方法数含构造器 ≤30，参数 ≤6，控制流嵌套 ≤3。内部类型计入外部类代码预算；全模块 ≤25,000 行物理行（含注释空行、排除测试/mock）仍需独立验收。

图中列出主要持久成员和公开/关键内部接口，属于接口草案，尚不是可直接编译的 Java API。字段类型中的 Map、计数器、快照表示数据用途，不授权新增线程池、锁或每请求包装。构造器、普通 accessor 未逐项展开，仍计入最终预算。部分异步协议尚待竞争测试证明。

符号：+ 公开，− 内部；空心三角为实现/继承，空心菱形为持有，虚线箭头为调用或只读依赖。分区图只画区内关系；跨区关系见总图与末尾依赖表。

                                      附属接口、资源句柄和状态数据

                                      下列为 32 组协议说明，部分一组包含多个实际类型；不是“额外类型为零”。实现前需确定具体声明总数，禁止把顶层类改成内部类当作复杂度下降。现有公共模块的 Request、Response、Config、EngineGrpcClient、FlexMonitor、ExecutorStats 等复用，不重新定义。

                                      归属 / 类型 性质 字段 / 方法 约束
                                      RequestContext.Snapshot 只读快照 request generation；route identity；取消原因；发送阶段；deliveryId；响应；Prefill/Decode 结算进度；deadline 不能包含可写 Future、线程池、Endpoint 锁；快照数据只供读取。
                                      RequestContext.Cancellation / Deadlines 请求事实 取消原因与时间；request/inactivity/visibility 的 deadline token 和到期时间 deadline token 用于丢弃旧定时器回调；不能只靠 requestId。
                                      RequestContext.SendState 枚举 NOT_STARTED / MAY_HAVE_SENT / ACKNOWLEDGED / FINISHED NOT_SENT 结果可确定本次未发送；异常不能自动倒退成 NOT_STARTED。取消独立于发送事实。
                                      RequestContext.ReleaseProgress 请求事实 prefillReleased；decodeReleased 只在对应精确资源释放成立后更新；取消标记不等于资源释放。
                                      RequestRoute.RouteIdentity 不可变身份 requestId；requestGeneration；routeId；Endpoint generation 新请求、新路由均不能复用旧操作身份；使用已有身份字段收敛，不再另建一层索引。
                                      PlacementQueue.PlacementItem / Scan 队列数据 精确请求身份；入队序号；排序字段 / bounded candidates；cursor；version 游标属于队列；调度器不读取默认实现节点。扫描不改请求生命周期，过期候选由 Scheduler 通知 Lifecycle。
                                      PrefillRequestQueue.QueueItem 只读输入接口 requestId()；priority()；enqueueSeq()；enqueuedAtMs()；expiresAtMs()；seqLen()；hitCache() 真实 route 和冻结预测输入使用同一字段契约；比较器不读取可变 Context。
                                      PrefillRequestQueue.Snapshot 不可变快照 version；orderedItems；Comparator<QueueItem> 比较器自身必须稳定；允许排序规则依赖的状态必须在快照中冻结。预测不得重新解释 priorityOrdering。
                                      PrefillRequestQueue.Factory 工厂接口 create(defaultOrder): PrefillRequestQueue 自定义实现可提供自己的规则；预测只读取实际队列 order，不再读取传入的默认值。
                                      GroupPlanner.Selection / GroupLimits 不可变选择 orderedPrefix；predictedMs；readyAt；reason / request、token、KV、窗口和预测上限 执行只接收策略选中的成员；不允许自行换人。GroupPlanner 只支持有序前缀。
                                      SelectionResult / PlacementAttempt 结果协议 策略：selected identity 或 failure/blocker + 原始原因；执行：原策略结果 + resource failure（如有） 策略结果保持原样；选中后资源竞争失败单独报告，不能把容量竞争重新包装成策略判断。归已有策略接口/Selector，不新增管理层。
                                      DecodeSelectionStrategy.CapacityReader 只读接口 read(expectedEndpointIdentity): CapacitySnapshot 精确身份失效返回 unavailable；不能获取或释放资源。只读入口不泄露 DecodeEndpoint。
                                      WorkerEndpoint.Use 现有 generation 使用权 精确 generation；一次性归还状态；close() 跨退休保护。已有的使用计数必须覆盖接受与交接窗口；不能因更名丢掉排空保障。
                                      PrefillEndpoint / DecodeEndpoint.Reservation 资源句柄 endpointGeneration；resource kind；reservationId；route 或 batch identity 不可变能力身份；消耗状态只在账本记录。批次预留绑定 batch，不绑定队头请求。
                                      PrefillEndpoint.RequestRecord / BatchRecord 资源记录 精确身份；RESERVED/COMMITTED；预测工作；Engine 进度；batch 成员关系 队列排序不是资源状态。批次预留尚无提交成员时仍占批次容量；request cancel 不直接替代 batch rollback。
                                      DecodeEndpoint.RequestRecord / PreemptionRecord 资源记录 精确 reservation；KV/slot 占用；投递事实；抢占 claim 与已确认清理事实 Request 取消与远端资源释放分别记录；未知发送保留必要占用。
                                      ReserveResult / CommitResult / ReleaseResult 资源结果 成功 + 精确身份；或容量不足、身份失效、generation 下线等失败原因 不携带 scheduler retry 动作；允许局部提交失败但不能修改已失效资源。具体枚举在实现前逐项覆盖现有结果语义。
                                      ReleaseEvidence 不可变证据 NOT_SENT；ENGINE_COMPLETED；REMOTE_CLEANED；GENERATION_RETIRED_WITH_PROOF；附精确操作身份 退役本身不意味着远端资源消失；代际清理必须有既有协议支持的证据。禁止 force=true。

                                      Delivery.SendProgress / Result 操作事实 共享 RPC 是否开始、完成；逐成员 DELIVERED / NOT_SENT / REJECTED / UNCERTAIN；cause 共享 RPC 进度不替代 Context 逐请求状态；异步结果先完成后订阅也必须可见。
                                      DeliveryExecution.DeliveryPermit 设施句柄 容量额度；payload bytes；一次性归还；close() close 只归还设施容量，不释放请求在 Engine 的资源。与请求资源句柄不能合并。
                                      DeliveryDispatcher.SubmissionResult 提交结果 实际成员前缀；blocked index；resource cause；投递标识 Scheduler 明确决定是否接受前缀；提交失败不负责选择下一请求。
                                      DecodePreemption.Attempt / Result 抢占操作 attemptId；incoming identity；victim identities；截止时间；完成结果；成功新预留 取消等待不等于资源回收；成功预留必须由当前 incoming request 接收或撤销。

                                      并发、替换和停服约束

                                      资源提交与发送资格：Context.beginDelivery 与 cancel 在同一请求锁下竞争：取消先成功则拒绝发送；发送资格先成功则保守视为可能发送，后续取消必须遵循远端 fencing/确认协议，不能先清本地资源。保留两个边界，不承诺跨 Prefill/Decode/Context 的全局原子提交。Endpoint 锁内禁止获取请求锁、RPC、预测或回调；取消后失败走统一未发送结算。

                                      Delivery 合并：只统一临时资源负责人和数据，不把逐请求身份合成一个 batchId；不新增每请求包装层，替换已有 Member/Claim 后需实测分配。

                                      RequestSignals 删除：完成先于订阅、重复完成、订阅与完成竞争均需验证；不为所有请求预建多份 Future。

                                      响应流程重写：必须保持现有对外 Future 的取消与完成语义。普通 CompletableFuture 替换不够；必要拦截逻辑归响应组件并计入预算。

                                      停服和下线：ApplicationLifecycle（现有 API 模块类，图外）仍拥有停服顺序；停止新工作后允许已登记工作的清理，不能先关闭回调所需执行器。

                                      依赖装配：Lifecycle、Scheduler、Dispatcher 有双向通知。配置先构造再一次性 bind，最后启动；bind 只能启动前执行且非可替换运行状态。不使用新的依赖袋绕过六参数限制。

                                      预算可行性：64 是顶层类型目标；附属协议与内部类型必须另外计数。合并后的 Endpoint 900 行、Dispatcher 850 行是待验证预算，不能用拆分隐藏超标。

                                      删除 SchedulerLoop：RequestScheduler 显式暴露 start/schedule/stop/awaitStopped 和事件入口；实现拥有触发方式，默认 QUEUE 直接拥有原有调度线程，planner 池继续执行选择和组批。停止必须取消唤醒并等待已接受的调度工作；不能等待自身。

                                      生命周期与请求状态：保留 RequestLifecycle 和 RequestContext；删除重复终态、通用 Granted/Denied 授权结果及无职责转发。Context 不调用 Scheduler、Endpoint、RPC、Future 回调；Lifecycle 在请求锁外执行这些副作用。

                                      接口调用的锁与副作用约束

                                      入口 约束
                                      策略 / GroupPlanner / 预测 只读冻结输入；不保留借用数据；无资源操作。预测、RPC、Reporter 不在资源锁内调用。
                                      队列修改与 Prefill 提交 使用现有共同锁保护成员变更与账本提交；Queue 不取得 Context 锁，不执行结算。
                                      Context 状态转换 只持有单请求锁；发送资格与取消竞争。Endpoint 锁内禁止反向进入 Context，跨 Endpoint 不新增全局事务锁。
                                      Endpoint commit / rollback / release 校验精确 generation、route 和 reservation；返回变化，通知和请求推进在解锁后执行。
                                      DeliveryDispatcher.submit 接受已选择成员和明确的前缀规则；资源竞争返回独立失败，不改写策略结果。RPC 模式与仅路由发布模式保留区别。
                                      ApplicationLifecycle 保留 API 模块现有负责人。stop admission → stop producing work → drain accepted delivery/cleanup/response → close pools；实际顺序以既有并发保障验证。
