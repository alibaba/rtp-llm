角色登记与 Worker 事件反馈

资源记账按角色保留；反馈在登记创建时关联本次选路；完整路由由 Balance 持有。

01问题不是角色不同，而是关联方式不一致

当前实现把“建立事件关联”和 P / Encoder 的“本地提交”绑定；Decode 没有相同提交步骤，转而反查上层对象。

Prefill / Encoder

提交时保存完整 WorkerRoute；反馈沿 route → ctx → scheduler 传递。

Decode

保存角色登记；反馈时按 ID 查 Repository，再读 Context 的当前 route。

Scheduler

将 Worker 接口强转回上层类型，再逐字段构造内容近似的事件。

Decode 多轮执行需要持续跟踪实际占用；登记与上报存在时间差，需要本地未确认预留。这些事实支持不同的记账规则，但不要求不同的请求导航方式。

设计边界：Worker 报告“本机哪个精确登记发生了什么”；Balance 判断“属于哪次选路，是否影响整个请求”。不能把本地 COMMITTED 与 Worker confirmed 当作同一种状态。

02完整流程 · 从选路到结束

从上向下阅读；横向箭头表示职责交接。每个角色重复步骤 ③—⑤。异步上报可能穿插在登记之后的任何阶段。

Balance 业务处理Endpoint 资源处理失败与清理边界虚线：锁外事件通知
部分角色登记失败时，如何退出？

例如 D 已登记而 P 容量不足：Balance 清理已经取得的精确登记。纯本地预留可以回滚；Worker 已确认占用时不能当作回滚成功，需要进入必要的远端清理。只有旧选路资源达到允许重试的条件，才能开始 S2。Direct / Queue 根据失败结果决定拒绝、等待或抢占。

为什么要检查精确登记，而不只检查 Endpoint 在线？

Endpoint 可能仍可用，但本次登记已被完成反馈移除。最终提交必须检查本次登记仍然有效，而不是只检查机器在线。具体检查位置和原子边界需通过并发测试确认，不能把多次检查解释为全局原子提交。

03资源实现保留角色差异

角色 登记时 执行期间 结束与回滚
Prefill 预留计算量 本地提交选择，处理活动与完成反馈 按登记阶段回滚；完成后清理本角色资源
Decode 预留请求数、硬 KV、预估 KV Worker 确认后扣除未确认预留；持续跟踪多轮占用 已确认占用不可当作纯本地预留回滚
Encoder 预留自身资源 提交并处理执行反馈 按自身登记与完成规则处理

统一反馈边界不意味着统一容量公式、提交阶段或资源释放条件。Decode 不新增仅为形式一致而存在的 commit。

04提交前反馈 · 三个阶段分别处理

SelectionAttempt 早于完整路由存在。角色登记对外可见时，必须已经能把事件交给这次选路。

事件 Endpoint 先做什么 Balance 决定什么
活跃 / Decode 确认 更新本机占用和观测 更新请求活动与可见性；已确认资源不能直接回滚
Endpoint 关闭 停止接纳，处理对应登记 阻止无效提交；未发布且可安全回滚时允许重试
完成 / 执行失败 先确认上报属于本次登记，再处理资源 根据角色、阶段与有效选路决定请求是否结束
P 完成且仍有 D 清理 P 资源 继续等待 D，而非结束整个请求
未决前提：当前 P / D / Encoder 对提交前完成反馈的处理不同。目标方案不能机械扩大接受范围；先核实生产协议、完成记录保留规则和请求 ID 重用约束，再用测试固定行为。

05取消、超时与晚到事件

交错场景 必须保留的隔离
S1 结束，S2 已开始 S1 事件不改变 S2 的执行结果；仍可完成 S1 的必要资源清理
相同 requestId 的新请求实例 旧接收关联仍指向旧实例，不能按 ID 转投新实例
旧 Endpoint 代际晚到事件 不能应用于新 Endpoint 的登记，核对精确来源与登记身份
旧原始上报匹配到新登记 不能靠回调解决：必须先确认协议提供的执行身份或 ID 唯一性约束

06职责与接口 · 保留什么，删除什么

对象 负责 不应暴露 / 承担
Endpoint 本角色登记、容量、上报匹配、锁外通知 读取上层快照、寻找完整路由、决定其他角色清理
Registration 精确身份、角色状态、窄事件接收入口 访问其他角色登记的导航接口
SelectionAttempt 标识一次选路，关联请求实例并隔离重试 重复保存 Endpoint 资源账本
RequestRoute Balance 内汇总角色结果，供响应与清理使用 作为 Worker 反馈和排序的万能入口
RequestContext / Scheduler 请求状态、跨角色影响、超时取消、清理协调 复制本机资源确认状态作为另一份容量来源

接口示意 · 不是已落地代码

// Balance：选路开始时建立关联，完整路由此时还不存在。
var selection = context.beginSelection();
WorkerEventSink events = event -> scheduler.onWorkerEvent(selection, event);

// Endpoint：回调与精确登记一起创建，再将登记发布进本地账本。
var registration = endpoint.tryRegisterSelection(roleInputs, events);

// P / Encoder：只提交本角色登记，不接收完整 RequestRoute。
prefillEndpoint.commitSelection(prefillRegistration);

// Endpoint：持锁处理资源；解锁后发布精确登记事件。
events.onEvent(event);

// Balance：使用原来的请求实例和选路身份，不按 ID 寻找当前路由。
scheduler.onWorkerEvent(selection, event);

事件优先复用现有登记身份和事件类型。Endpoint、role 若可由登记可靠取得，就不重复保存。完整路由的 REMOTE_CLEANED / REMOTE_FENCED 仍由 Balance 处理，不强塞进角色登记事件。

删除导航与转换

Worker 中完整 route 引用；Decode 为反馈反查 Repository；接口强转与重复事件搬运。

逐调用方清理

排序只传所需序号；TTL 继续精确核对登记。WorkerRequest 的抢占用途须单独核对，不能直接整类删除。

不增加平行机制

不新增全局登记映射、通用事件总线、事件缓冲队列或第二套资源状态。

回调可能间接保留上层请求引用，因此还需核对登记、事件与清理结束后的引用释放；“不暴露导航”并不等于对象之间完全无引用。

07验证先行 · 再替换旧路径

  1. 先核对原始上报身份。同一 Endpoint 代际内能否重用 ID？完成记录保留多久？旧记录如何避免匹配新登记？
  2. 固定提交前行为。角色登记已创建、完整路由未关联时发生完成、确认或关闭；不得静默错误提交，也不得误伤可回滚重试的请求。
  3. 固定身份隔离。S1 晚到事件、相同 ID 新实例、旧 Endpoint 代际，以及旧登记清理仍需完成的情况。
  4. 验证资源与请求分工。P 完成继续等 D；Decode 确认后不重复记账、不直接回滚；失败清理其他角色。
  5. 验证并发边界。用锁存器控制登记发布、事件回调、取消与提交交错；证明回调在 Endpoint 锁外。
  6. 迁移后删除旧机制。核对关闭、TTL、排序和抢占调用方，再删除导航接口和重复事件转换；运行相关 UT 与全项目格式检查。
