# Mock 行为修改原则

在本目录开发、调用或评估 Mock 能力，以及由此涉及的 Mock engine 修改，遵循以下原则：

- 发现 Mock 能力不足或存在 bug，需要优化、扩展或修复时，先阅读 real 对应功能的源码及相关测试，确认协议、状态转换、资源所有权、取消与异常处理语义，再设计修改；不能只根据 Mock 当前实现或让 case 通过的需要推导正确行为。
- 优先仿照 real 的行为语义实现。Mock 可以简化计算和部署机制，但应明确保留哪些语义、简化哪些机制；Mock 专属的容量限制、故障注入或保护措施应明确标识，不得当作 real 行为。
- 找不到对应实现、real 行为存在歧义或暂时无法对齐时，明确说明依据不足和模拟边界，不凭猜测宣称对齐，也不通过放宽 case 判定掩盖差异。
- 为修改增加或更新行为回归测试，覆盖相关正常路径与错误分支，并在变更说明中指出 real 的具体源码位置及对齐依据。支持范围改变时更新现有行为说明；不新增逐文件登记或整文件哈希门禁。Mock UT 通过只证明所测行为，不等于完成真实引擎差分验证。

# 文档维护规则

本规则适用于本目录所有说明文档，包括 `docs/`、`data/README.md` 及配置、源码旁的 README。

- 只记录现行、可复用的规则、架构、接口契约、运行方式和故障排查方法。正文使用中文，代码标识符保留英文。
- 禁止添加历史叙事：日期流水账、开发过程、迁移经过、已完成清单、某次修复或验证记录。
- 禁止新增单一 case 说明页，或在通用文档里展开某个 case 的拓扑、阈值、阶段断言和专属运行记录。实例参数和断言以 YAML、程序及测试为准；文档说明公共选择、执行与判定方式。
- 禁止添加实验报告、测量表、某次运行结论、部署 ID、具体发布版本、采集窗口、运行 SHA 或待办进度。报告与证据写入 `run/` 或仓库外归档，不迁入新的文档归档目录。`run/` 是忽略的本地输出目录，不得强制加入 Git；入库的固定输入和配置按 `data/`、`config/` 的规则维护。
- 文档可以说明版本兼容规则、当前支持范围和已知实现限制；用现在时描述契约，不叙述变更过程。
- 命令示例使用占位路径和必要的最小参数。不得把一次实验的规模、预算或门槛包装成通用默认值；默认值以源码、配置和 `--help` 为准。
- `data/README.md` 只保留分类、命名、准入、选择、元数据、归档和兼容规则及用法。各文件的来源、统计、SHA、窗口和标定参数留在 manifest/profile/config，不逐文件抄写。
- `docs/architecture/` 放组件职责、数据与协议语义；`docs/development/` 放开发机操作与通用开发说明；`docs/whale/` 放该运行环境的配置和验收规则。不恢复 `docs/reference/` 或单 case 文档树。
- 同一契约只在一个主题维护正文。目录 README 只说明用途并导航，不重复运行教程，不维护实例数量、完整字段清单或 case 专属阈值。
- 移动、删除文档时同步修正导航、相对链接及其他引用；将有用的公共规则提炼后合入现有主题，不保留重复正文或重定向空壳。

提交前检查：内容是否脱离某次运行仍然成立；是否重复了配置/manifest；链接目标是否存在；命令参数是否与实际入口一致。纯文档治理不修改运行代码、数据工件或门禁阈值。
