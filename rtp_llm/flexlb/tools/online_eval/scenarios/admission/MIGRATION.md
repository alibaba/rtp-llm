## Prefill batch token budget checkpoint

All four legacy programs retain batch-window only,1P/2D, PRIORITY, queue60000ms and a100ms master collection window. Startup `prefill_perf` replaces the prefill perf object with fixed_ms3000/scale1/max_batch_requests0 and explicit max_batch_tokens1024(split and split_fifo),2048(boundary),or0(regroup_disabled). Zero/zero is preserved as disabled; it is never omitted or emulated with a dynamic perf update. The startup field is supplied by core commit42b7d98b0d (local dependency fc0e862083).

- `engine_prefill_token_budget_split` → `split`: four512/output2 concurrent submissions10ms apart, deferred Fetch; park max(waiting,prefill_waiting_batches)>=1 within10s;8s Master ledger observation; successful drain with45s per-stream cap; shared nonzero batch_id for all four; empty engine park10s, master clean30s, fresh recovery.
- `engine_prefill_token_budget_split_fifo` → `split_fifo`: the same burst, then start all four concurrent Fetch consumers before the8s observation. Actual concurrent wait-return stamps must form two pairs with intra-pair gaps<=1s and inter-pair gap>1s, independent of arrival/request-ID order. Engine end_ms clusters at1000ms separation are diagnostic only. Ledger, successful completion, empty park, master clean and recovery are verdicts.
- `engine_prefill_token_budget_boundary` → `boundary`: one512/output2 baseline with15s stream cap; four concurrent live timed requests10ms apart with15s caps; no prefill_waiting_batches during2.5s, then5s atomic ledger observation. Four completions and index-method p50 Schedule-to-consumer-end degradation<=50% against the baseline are required. Missing/invalid timing is not a pass. Empty park, master clean and recovery follow.
- `engine_prefill_regroup_disabled_verbatim` → `regroup_disabled`: zero/zero startup budget, four deferred requests, no prefill_waiting_batches over2.5s,5s atomic ledger observation, successful45s per-stream drains and one common nonzero original batch_id; empty park, master clean and recovery.

Each Master ledger series requires peak batches==1, peak prefill members==4 and non-increasing scheduler_inflight. Split programs additionally require an intermediate member count; atomic programs forbid one. Full raw endpoint rows are retained. Missing endpoints/counters or failed observation I/O is ERROR rather than default-zero evidence, an explicit strengthening of the legacy sampler. Final zero belongs to master_clean rather than an invented in-window convergence check.

Before/after executed-batch counter deltas and lifetime max batch size are preserved as observations: intended2b/4r/max2 for split and1b/4r/max4 for atomic programs. A construction mismatch does not silently become a verdict failure; the original cases excluded it from `passed`. The engine FIFO shape check likewise remains diagnostic. No legacy case/helper function is called by the programs. Eight focused budget tests include full execution of all four programs, Master re-admission, wrong batch identity, degraded TTFT, diagnostic-only shape mismatch and a barrier proving all burst submissions precede ACK waits.
