# 输出长度热更新

## 这个端点解决什么问题

Mock 控制端口提供 `GET /output_length` 和 `POST /output_length`，用于在不重启引擎的前提下调整 mock 引擎的停止输出长度模型（EOS 模型）。

它只改变"生成到多长就停"这一目标，不改发给 master 的请求输入长度，也不改调度配置。

## 调用流程

先 `GET` 读回当前配置并保存，作为回滚基线，再 `POST` 新配置。

回滚：把保存下来的 EOS 对象作为 `eos` 值原样再 `POST` 一次。
关闭模型、恢复原有请求长度行为：`{"eos":{"enabled":false}}`。

## 请求形态

```json
{
  "eos": {
    "enabled": true,
    "distribution": "geometric",
    "mean_tokens": 770,
    "seed": 20260913
  }
}
```

`POST` 完整替换 EOS 配置，校验通过后才应用。字段约束：

- `mean_tokens` 必须为有限数值且至少为 1；`seed` 为 64 位整数。
- 不支持的分布或未知字段返回 400。

`GET` 返回 `engines.<name>.eos` 与 `runtime_override`。

## 作用范围

- 默认更新当前控制进程下的所有 P/D 引擎；可加 `"engine":"prefill-0"` 定向单个引擎。
- **P 也要更新**：本地 PD 链路里，P 在生成请求 shape 时就抽样输出目标并把目标传给 D。只更新 D 不会改变 P 已经确定的长度。
- **独立 Pod 模式**需分别对各 Pod 的控制接口下发，接口不负责跨 Pod 事务。

## 语义边界

- 只影响之后新生成的请求 shape；已生成 shape、排队中、在途请求的输出目标不变。
- 保留 `min_new_tokens`、`max_new_tokens`、`ignore_eos` 及显式回放长度规则。
- `mean_tokens` 是几何分布参数：最小长度、上限和请求策略都会改变实际观测均值，它不保证每个请求恰好输出该长度。
- 缓存、P/D 性能公式、scale 和集群规模不变，无需重启。
- 更新在每个模型内通过不可变对象一次替换；多个引擎逐一应用，不保证跨引擎同时切换。切换期间被重建的请求可能使用新参数。
- 热更新仅对当前进程有效，不写环境变量或仓库；重启后恢复启动配置。动态新增的引擎使用其启动模型，扩容后应重新查询并下发。
