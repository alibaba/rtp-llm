# running/waiting 外部项与压力曲率消融

本报告是 [LatencyPhaseLeastSquaresReport.md](LatencyPhaseLeastSquaresReport.md) 的后续实验。只修改离线回算工具，**没有改生产公式或上线参数**。目的：检查 running/waiting 已在非线性内部的基础上，再加非线性外部直达项、让曲率随压力变化，能否提高 MI308 高压精度，同时保持 RTX 5000 和低压稳定。

## 先给结论

1. **非线性外单独加 `a*running+b*waiting`，两个硬件、两个窗口都没有稳定收益。** A/B 的 MI308 全压力训练、高压留出 MAE 从 13975/11733 变成 14184/11746 ms；RTX 从 2860/1656 变成 2750/1666 ms。A RTX 的小幅收益没有跨窗口复现，且不少拟合不收敛。
2. **曲率随压力变化有一条待验证的 MI308 高压线索，但目前不是可用方案。** 用高压样本单独训练再测高压，双计数曲率项使 MI 的 A/B MAE 从 12534/10642 降至 11967/10278 ms，约 4.5%/3.4%；只用 waiting 曲率项为 12449/10219 ms，约 0.7%/4.0%。然而**全压力训练**的高压预测在 A/B 并不同时改善：双计数曲率为 13267/11978 ms（基线 13975/11733），只用 waiting 曲率为 16784/11981 ms。A MI 双计数曲率全局 10 个节点仅 1 个优化器收敛，低压留出还出现极端外推；不能以高压专拟的收益判上线。
3. **外部项与曲率项一起加入没有产生稳定叠加收益。** A/B MI 全压力高压 MAE 为 14710/11965 ms，均比基线差；只保留 waiting 曲率并叠加外部项为 14719/12049 ms，也更差。高压专拟虽改善，跨压力泛化仍失败。
4. **相关性解释了部分不稳定。** 高压训练样本上，waiting 与既有 `precedingRequestCount` 的节点中位 Pearson，A/B MI 为 0.9973/0.9975，RTX 为 0.9951/0.9950；RTX 新增外部 waiting 与原非线性内部 waiting 的目标梯度在两个窗口节点中位绝对相关约 0.99999/1.00000。MI 曲率 waiting 与内部 waiting 梯度也约 0.85/0.98。新增系数常可替代旧系数，拟合参数的符号和大小不能直接解释为新的物理作用。
5. **仍无法裁定“缺特征”与“公式形式不足”的唯一根因。** 这些候选只是曲率的一种正值参数化和几个加性项；尚未包含与调度时刻严格对齐的 decode 剩余工作量。离线高压专拟的小收益不能抵消全压力外推、低压和收敛风险。

## 公式与实验口径

线上 v21 基线可写为

```text
L = (p0 + p1*R + running_token_terms + p10*W
     + waiting_token_terms + p16*running_elapsed/1e6) / 320
y = max(0, p7 + 1500*[shape(L,p8)-shape(p0/320,p8)]
           + p9*total_prompt + p15*preceding)
shape(x,k) = x + sqrt(x*x+k)
```

`R`、`W` 分别是 running/waiting prefill 请求数。非线性外已有 `p15*preceding`，但它包含更多此前请求，不是分别建模 R/W。新增项分别为：

| 名称 | 变更 |
| --- | --- |
| `base` | 线上基础公式，无新增项。 |
| `direct` | 在非线性外加 `a*R+b*W`。 |
| `curvature` | 令 `k(R,W)=softplus(q0+cR*R/10+cW*W/100)^2+1e-8`，在 `shape(L,k)` 使用它；零负载锚点仍用 `k(0,0)`。 |
| `curvature_waiting` | 同上，但只拟合 `cW`。 |
| `both` | `direct` + 双计数 `curvature`。 |
| `direct_curvature_waiting` | `direct` + 单 waiting 曲率。 |

`softplus(z)=log(1+exp(z))` 用数值稳定形式实现，保证曲率为正；`cR`/`cW` 允许正负，没有给它们人为设物理范围。`q0` 从线上 p8 变换而来，零负载时仍为 p7。曲率变化**不是**“所有参数随压力独立变化”：它只改变共享非线性函数的形状；外部计数项则是额外的直达斜率。

沿用前报告的两个独立日志窗口 A/B、逐节点拟合、每 8 分钟最后 2 分钟整块留出，以及按输入计数定义的低压 `R<=4,W<=4`、高压 `W>=33`。每个模型分别做全压力、低压、高压三个训练集合的 log1p 平方最小二乘；下表主口径是**全压力训练**，并另列高压专拟的高压留出。每节点只从采样窗口开始前参数初始化，优化上限 1200 次函数评估；非凸问题没有全局最优保证。汇总 MAE 按留出样本数加权；`收敛` 为全压力拟合达到 SciPy 终止条件的节点数。基础公式与日志原始预测的最大复算差不超过 `5.17e-10 ms`；所有新增解析梯度已做数值差分测试。

## 相关性与可辨识性

以下相关系数先在每节点训练样本上计算，再取节点中位；不是把所有节点的时间序列硬合并。Pearson 描述线性共变，Spearman 用来核对排序趋势；都**不是因果或条件独立证明**。

| 训练高压段的相关关系 | A MI | B MI | A RTX | B RTX |
| --- | ---: | ---: | ---: | ---: |
| `W` 与 `preceding`，Pearson | 0.9973 | 0.9975 | 0.9951 | 0.9950 |
| `W` 与 `preceding`，Spearman | 0.9972 | 0.9961 | 0.9933 | 0.9920 |
| 线上基础预测有符号 log 误差与 `W`，Pearson | +0.427 | +0.007 | -0.084 | +0.221 |
| 同一误差与 `W`，Spearman | +0.465 | +0.220 | -0.156 | +0.105 |
| 线上综合预测有符号 log 误差与 `W`，Pearson | +0.001 | -0.054 | +0.063 | +0.227 |

相关性的符号/强度并非跨窗口和硬件一致，尤其 RTX 的基础误差与 waiting 方向翻转；所以不能单独按 waiting 正相关设计普遍的误差反馈。压力越高，`W` 与 `preceding` 越像同一列：全压力样本的 Pearson 节点中位 MI 仅 0.60/0.85，RTX 0.97/0.98；高压条件下四组全部高于 0.995。外部 `b*W` 与现有 `p15*preceding` 在高压段会竞争同一信号。

更直接的可辨识性检查是**拟合损失的 Jacobian 列相关**，它衡量“改这个参数对预测的作用”是否与另一个参数相似：

| 全压力拟合，梯度列绝对 Pearson 的节点中位 | A MI | B MI | A RTX | B RTX |
| --- | ---: | ---: | ---: | ---: |
| 外部 `W` vs 内部 `W`（direct） | 0.20 | 0.84 | 0.99999 | ~1.00000 |
| 外部 `W` vs 既有 `preceding`（direct） | 0.83 | 0.93 | 0.88 | 0.85 |
| 曲率 `W` vs 内部 `W`（curvature） | 0.85 | 0.98 | 0.32 | 0.14 |
| 曲率 `W` vs 内部 `W`（curvature_waiting） | 0.85 | 0.98 | 0.34 | 0.17 |

在 MI 曲率单独加入时，waiting 曲率系数 A/B 全压力模型为 10/10、10/10 节点正值（单 waiting 曲率为 9/10、10/10）；但与外部计数同时加入后，双计数组合 A/B 仅 6/10、3/10，单 waiting 组合仅 3/10、2/10 为正。**符号在等价模型间不稳定**，与梯度共线和优化未收敛一致，不能把正系数解读成“硬件真实曲率一定随压力增大”。即便某些新增参数的局部 Jacobian 满秩，接近 1 的梯度相关仍会使有效条件数很差。

## 判定与可复核范围

这轮实验支持一个有限判断：让 waiting 影响曲率在 MI308 **高压专拟**中有重复出现的小幅信号，但未通过全压力泛化、优化收敛及跨硬件验证。外部双计数没有稳健收益，与曲率叠加还增加竞争和不稳定；B 窗口单 waiting 曲率拟合还触发了 SciPy trust-region 的除零数值警告。**不建议现在修改线上公式**。它没有否定其他压力曲率函数，也没有证明一定缺 decode 特征。要区分两者，仍需决策时刻同步的 decode 剩余工作量及前后请求顺序，并在同样时间留出上比较“现有公式+真实新特征”与“完整特征+新公式”。

回算工具为 `AnalyzeLatencyPressureFormula.py`，单测为 `AnalyzeLatencyPressureFormulaTest.py`。例如 `OPENBLAS_NUM_THREADS=1 python3.10 aios/navi_sched/test/AnalyzeLatencyPressureFormula.py /tmp/navi-rate-config-aware-0106 --variant curvature`；把路径换为独立窗口、variant 换为表中其他名称即可重复。逐节点 JSONL 输出在本机 `/tmp/navi-pressure-formula-{current,independent}-{variant}.jsonl`，不随报告提交；原始采样窗口同样在本机 `/tmp`，因此远端只保存工具、测试和汇总结论，而非完整日志证据。
