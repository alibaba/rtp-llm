# MI308 高压非线性形式诊断

## 问题和可辨识性

当前基础模型先由调度特征生成标量 `u`，再计算
`F(u,K)=u+sqrt(u*u+K)`。总预测还包含偏置、prompt 与 preceding 的直接项。
`u` 是可学习的特征组合，**不是独立测量的真实工作量**。对于任意可逆变换
`h`，`F(u)` 都可改写为 `(F compose h^-1)(h(u))`；因此仅从现有
`(特征,耗时)` 对，无法唯一恢复硬件的物理非线性函数。这里能检验的是：
现有特征能否由一个标量索引加一条曲线解释，以及加入交互后是否能稳定泛化。

## 数据与评分

- A：`/tmp/navi-rate-config-aware-0106`，MI308 10 节点、RTX PRO 5000 9 节点；
  B：`/tmp/navi-independent-combined-original-0106`，各 10 节点。每节点独立训练，
  仅评分 `waiting>=33` 的高压样本；A 的 MI/RTX 样本数为 11473/8833，
  B 为 31195/23232。表格为按样本数加权的 MAE，单位 **秒**。
- `全样本` 是训练内误差，不是未来预测；`随机留出` 是每节点随机 20%；
  `时间留出` 是按 event time 排序后的最后 20%。三者的训练集不同，
  不能用全样本误差减去留出误差声称因果收益。
- 新增的神经索引模型使用相同 12 个现有特征、相同两项线性旁路；
  `u` 的维数分别为 1、2、4，后接两层宽 32 的 SiLU 网络。
  对每个训练划分仅用训练样本计算标准化量，Adam 训练 1500 轮、2 个种子，
  按训练平方损失选择种子及轮次。没有训练 residual、没有使用留出真值选模型。
- 旧公式的工作段由**高压全样本专拟**参数事后标记：
  `u/sqrt(K)<-3` 为负向远端，`|u/sqrt(K)|<=3` 为过渡区，
  `u/sqrt(K)>3` 为正向远端。这些标签不参与新模型训练；由于标记参数
  见过全样本真值，工作段留出统计仅用于定位，不是严格无泄漏的模型选择。
- 误差正负号采用 `真值-预测`：正值表示低估。下表是 MAE，没有正负号。

## 方法对照

单索引和多索引模型的结果如下。每格按 `全样本 / 随机留出 / 时间留出`
顺序给出高压 MAE，单位秒；同一窗口和硬件内，三个索引维数的拆分与训练配置相同。

| 窗口/硬件 | 1 维索引 | 2 维索引 | 4 维索引 |
| --- | ---: | ---: | ---: |
| A MI308 | 10.60 / 11.03 / 10.75 | 6.96 / 7.85 / 11.43 | 5.37 / 6.89 / 11.66 |
| A RTX 5000 | 1.89 / 1.95 / 2.16 | 1.77 / 1.87 / 2.08 | 1.79 / 1.93 / 2.59 |
| B MI308 | 11.19 / 11.22 / 9.78 | 9.80 / 9.95 / 9.15 | 8.36 / 8.86 / 10.04 |
| B RTX 5000 | 1.55 / 1.55 / 1.61 | 1.54 / 1.55 / 1.74 | 1.53 / 1.56 / 1.72 |

作为训练内参照，原 `F(u,K)` 高压专拟的 MI A/B MAE 为 8.91/10.98 秒，
RTX 为 1.93/1.54 秒。索引网络不受原公式的参数数目和零点约束；
4 维的训练内改进证明当前特征存在可利用的多变量结构，**不是生产候选收益**。
MI A 的 4 维模型时间留出有符号平均误差为 +1.61 秒，B 为 -0.45 秒；
偏差方向也不稳定。它只在高压训练，尚未检验低压零点，不能直接替换基础模型。

已完成的其它函数族实验作为交叉检查：

| 方法 | MI A/B 高压训练内 MAE (秒) | 留出与解释 |
| --- | ---: | --- |
| 固定原拟合 `u`，单调回归 | 8.42 / 10.72 | 只改一维外层形状，未接近 5000；该 `u` 见过全样本，留出结果不作独立验证。 |
| 固定 `u`，三次样条 | 8.72 / 10.90 | 同样未解决；`u` 的估计误差与曲线形状不能分开。 |
| 全特征加性样条 | 10.42 / 11.54 | 每个特征各自弯曲仍不足，暗示交互或缺状态。 |
| 全特征交互树 | 3.11 / 5.84 | 随机留出约 6.39 / 8.61；时间留出约 11.96 / 9.71。训练内大幅下降，时间外推没有同步改善。 |

上述树模型在全部压力样本上训练，再从中评分高压；其随机/时间留出的
高压样本口径与只训练高压的索引网络**不是逐样本配对**，只能比较量级。
已有树模型随机留出分组置换结果：MI 的 waiting token、preceding 数、
running token 在 A/B 都有明显误差增量；RTX 更集中在 waiting 数与
waiting token。置换会破坏特征间的真实相关性，增量只能表示模型依赖，
不能当作哪个特征具有因果作用或某个交互项一定有效的证明。
之前还试过直接平方、在原式增加 `w*u^2`、嵌套 `F(F(u))`、根号内二/三/四次
多项式，以及 waiting 平方、running×waiting 和 decode 代理交互；没有一个在
A/B、两硬件和低压约束上同时稳定达到 RTX 的误差水平。

## 工作段与压力段不能混同

下表的 `n` 是高压样本数；两个 MAE 分别为旧公式高压专拟的训练内误差、
4 维索引模型的**时间留出**误差，单位秒。它们不是同一训练/评分划分，
这里只看工作段分布和残留误差量级，不能把两列相减当改进幅度。

| 窗口/硬件 | 负向远端 n / 旧式 / 4维时间留出 | 过渡区 n / 旧式 / 4维时间留出 | 正向远端 n / 旧式 / 4维时间留出 |
| --- | ---: | ---: | ---: |
| A MI308 | 3208 / 7.59 / 10.46 | 7969 / 9.25 / 12.10 | 296 / 13.87 / 15.97 |
| A RTX 5000 | 1253 / 1.38 / 1.75 | 978 / 1.31 / 1.31 | 6602 / 2.12 / 2.97 |
| B MI308 | 3925 / 7.88 / 8.46 | 27270 / 11.43 / 10.31 | 0 / 无 / 无 |
| B RTX 5000 | 2380 / 1.58 / 1.79 | 943 / 1.62 / 1.99 | 19909 / 1.54 / 1.70 |

MI A/B 的过渡区占高压样本约 69.5%/87.4%，RTX 约 11.1%/4.1%；
RTX 高压主要在正向远端，MI B 完全没有正向远端样本。
这**不是**“MI 硬件的真实非线性更强”的证明：`u` 和 `K` 都是可学习参数，
且 MI/RTX 的 running 数、等待时间和流量分布不同。4 维模型在 MI A 的
负向远端和过渡区时间留出均超过 10 秒，不能把未解释误差只归因于某一个
`F` 的工作段。

## vLLM 执行路径核查

本节基于 `/home/zq103303/vllm` 的 `navi_sched` 分支 `08127ab61e`，
以及 NaviSched 当前工作树的适配器代码。10 月 3 日留存的启动配置显示：
MI308 为 `max_num_seqs=1024`、`max_num_batched_tokens=8192`、TP=2、
FP8 模型；RTX 5000 为 64、4096、TP=4、modelopt_fp4 模型。
`max_num_scheduled_tokens` 若单独配置可覆盖 batched-token 上限；这份留存
记录没有证明 10 月 6 日 A/B 窗口的所有运行参数仍完全相同。
两者不只是 GPU 型号不同，模型文件、量化和并行配置也不同。

- `vllm/v1/core/sched/scheduler.py` 的 `schedule()` 先遍历 `running`，
  给每个请求安排 token、分配 KV block，再让 `waiting` 使用剩余 token
  预算和 running 槽位。`running` 包含 prefill 和 decode；因此等待中的
  prefill 每轮能分到多少算力，取决于当前活动序列和实际 batch 形状。
- `vllm/v1/worker/gpu_model_runner.py` 按每个请求的
  `num_scheduled_tokens` 构造输入，并用已有 `num_computed_tokens` 加上本轮
  token 数形成 `seq_lens`，提交 attention metadata。单轮成本不仅取决于
  prefill token 总量，还取决于活动序列数、各自上下文长度、KV 布局、
  量化算子和 GPU 后端。ROCm 与 NVIDIA 后端选择也不同，但当前证据
  不能把差额分解到某个具体 kernel。
- `VLLMEngineObserver.py` 的 `_make_workload_contribution()` 把
  `remaining_total_tokens` 直接设为 `remaining_prefill_tokens`；它没有编码
  decode 序列当前的上下文长度或未来工作量。基础公式的 `running/waiting`
  token 特征也只描述 prefill，全部此前请求只通过一个
  `preceding_request_count` 标量进入模型。`running_elapsed_time_ms` 只
  累加 running **prefill** 请求。这里不是说要估计未知的未来 decode 长度；
  只是指出预测输入与 vLLM 实际执行输入不相同。
- 当前学习目标是 `AgentBatchR::startBatch()` 到 `finishBatch()` 的
  **prefill 完成墙钟时间**。多 chunk 时，它包括各轮执行之间的间隙，
  不是一条只由本 batch prefill token 决定的 GPU kernel 时间。

用 A/B 已记录的高压样本再核对容量状态。`preceding - waiting` 是
“当前活动请求数”的近似代理，`preceding - waiting - running_prefill` 是
活动非 prefill 请求数的近似代理；waiting 是 NaviSched 的容量划分，
并非直接读取 vLLM 内部队列，所以这里明确称为**代理**。两组数的
10/50/90 分位如下，单位均为请求数：

| 窗口/硬件 | 高压样本 n | 活动数代理 P10/P50/P90 | 非 prefill 代理 P10/P50/P90 |
| --- | ---: | ---: | ---: |
| A MI308 | 11473 | 1015/1022/1023 | 1010/1017/1021 |
| A RTX 5000 | 8833 | 58/63/63 | 57/62/63 |
| B MI308 | 31195 | 1016/1020/1023 | 1011/1016/1021 |
| B RTX 5000 | 23232 | 57/61/63 | 56/60/63 |

两种部署高压时都贴近各自 running 上限，但 MI 的活动序列规模约为
RTX 的 16 倍。此时 `preceding≈运行槽位上限+waiting`，
所以公式中的 preceding 线性项与 waiting 项、偏置高度混同；
只调 `p15` 或外层 `F(u)` 难以唯一识别实际执行成本。

独立的 9 月 10 日归档执行日志提供了早期版本的方向性对照，**不是**
10 月 6 日同负载硬件基准。按单轮且本 batch prefill 为 512–1024 token
筛选，MI 有 15999 条 batch 记录，墙钟中位 868 ms、同轮 decode 请求
中位 1018；RTX 有 6108 条，分别为 179 ms、63。日志按 batch 记录，
同一轮若有多个 batch 不构成独立样本。这表明差异已出现在单轮执行内，
不能全归因于“等待多轮”；但量化、TP、序列数、上下文长度和硬件都未受控，
不能把 689 ms 差额称为 MI 芯片本身的损失。

代码和现有日志支持的解释是：MI 在 1024 序列容量边界上执行混合
prefill/decode，一轮的实际成本随活动序列形状、长度和后端算子变化，
而 NaviSched 把它压缩成 prefill 工作量加一个请求数。这是**可检验的
结构缺口**，还不是已证明的单一根因；要确认哪一部分主导，需要同一
时刻的 vLLM step 级耗时、活动序列长度分布、实际调度 token 数及
GPU kernel profile，对齐到 NaviSched 样本，而不需要预言未来 decode 长度。

## 当前结论与下一步判别

1. 现有数据**没有辨识出一个可迁移的 MI308 固定非线性形式**。
   单调回归/样条反驳了“只把已拟合 `u` 的外层曲线换一下就够”；
   多索引和交互树则显示可见特征间有交互，但高容量模型的时间留出与
   A/B 跨窗口迁移仍差。交互树同节点跨窗口高压 MAE：MI A→B/B→A
   为 15.30/13.08 秒，RTX 为 5.85/8.59 秒。
2. 下一项最有辨别力的实验不是继续试高次多项式，而是取得**调度决策时**
   同步可见的 decode 剩余 token、已排程 token、队列/批次位置、running
   执行进度、KV 状态和 master/agent 时间对应关系。它们必须按请求 ID
   与结果对齐，不能把执行后状态回填到调度特征中。
3. 在同一硬件上控制请求长度、cache hit 和压力，分别扫 waiting、running、
   decode 剩余工作量；用受控实验测量近似独立的工作量轴，再做 GAM
   的二维交互、GP/样条响应面与稀疏符号回归。只有训练外时间块、
   A/B 窗口、压力升降方向和低压零点都稳定，且在线回算/真实压测复验，
   才能将具体函数定为候选。

本次只增加分析脚本 `CompareLatencySingleIndex.py` 及其单测，未改生产公式、
配置或上线。复算结果位于 `/tmp/navi-single-index-{A,B}-d{1,2,4}.json`，
工作段结果位于 `/tmp/navi-single-index-{A,B}-d4-regions.json`；这些是本机
临时文件，不是随仓库提交的数据归档。
