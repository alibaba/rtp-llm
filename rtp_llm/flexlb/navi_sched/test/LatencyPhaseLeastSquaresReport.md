# NaviSched 延迟模型：MI308 与 RTX PRO 5000 分段、全局及在线对照

## 结论先行

1. **现有证据不能把 MI308 的滞后单独归因于学习率或 Adam。** 在两个独立采样窗口，MI308 的压力上升段在线基础预测 MAE 分别为 9441/14479 ms；RTX PRO 5000 为 3069/2484 ms。但 MI308 的高排队状态、运行中请求数和持续时间远大于 RTX，两者并非相同压力分布的对照实验。MI308 两窗口内同一段的有符号偏差和部分相关性还会翻转。
2. **低压拟合参数不能可靠泛化到高压，但这不能直接证明公式错误。** 用调度时可见的 running/waiting 计数定义低压、高压，在同一时间留出集互相预测：低压模型对高压的节点中位 MAE，MI 两窗口约为 128431/400865 ms，RTX 为 18461/3296 ms；高压模型反向预测低压也明显变差。MI 低压拟合的 16 个有效参数在 A/B 分别有 7/10、10/10 个节点局部 Jacobian 缺秩。低压区域没有足够的高压特征变化，参数本身不能唯一确定；极端外推误差不能解释为真实线上延迟。
3. **高压内部仍存在 MI308 的显著未解释误差。** 高压样本单独拟合后，高压留出 MAE MI 为 12766/10642 ms，RTX 为 3001/1689 ms。加入已知特征的交互项或用相同输入的灵活非线性回归，都没有在两个窗口、两硬件上稳定改善。这不支持直接上线任何现有候选公式；但现有日志也不足以在“缺调度时刻状态”与“公式不够表达”之间作唯一归因。
4. **目前没有经过跨窗口、跨硬件、可辨识性与在线正反验证的可上线新公式或新特征。** `decode_only × waiting` 在两个 MI 窗口将静态全局留出 MAE 降低 8.4%/5.7%，但 RTX 反而恶化 2.2%/1.7%；它在高排队样本中与原有 waiting count 几乎完全共线。该结果是诊断线索，不是独立特征有效性的证明。
5. **更值得验证的是调度时可观测的 decode 工作量/执行进度，而非仅增大 running elapsed 的系数。** 已有快照含 `remainingTotalTokenCount`、`inFlightScheduledTokenCount`，基础拟合输入却主要取 prefill 工作量、总请求数与 running elapsed。MI308 在 `running=0, waiting>=33` 时仍有非常大的误差，说明 running elapsed 单独不能解释全部现象。现有样本缺少同步、因果正确的 decode 工作量，尚无法严谨回算这个候选。
6. **零点并非目前的主要失稳点。** 两个窗口中，在线综合预测在真值 `<256ms` 的 MI308 留出样本 MAE 为 36/51 ms；但高排队及上升段误差可达数秒至十几秒。任何候选若为降低总体 MAE 而破坏低压几十毫秒的精度，应判失败。

## 数据、口径和可复现性

- 两个原始窗口：`/tmp/navi-rate-config-aware-0106`（下称 A）与 `/tmp/navi-independent-combined-original-0106`（下称 B）。分析输入为从这些日志提取的逐节点事件、特征、目标耗时、更新前参数及预测。A：MI 10 节点 25447 样本，RTX 9 节点 17429 样本；B：各 10 节点，MI 67805、RTX 46468 样本。按节点计算，再按**样本数**加权汇总，而非先平均节点 MAE。
- 时间留出：`(event_time_us // 120000000) % 4 == 3`，即每 8 分钟的最后 2 分钟整块留出。A 留出 MI/RTX 8078/5328 条，B 为 17125/10822 条。留出按绝对事件时间，不是随机拆散单条样本；但训练块与留出块仍属相近流量周期，不能替代另一日/另一部署验证。
- “上升段”是全部节点的 waiting 数量按 30 秒分桶、再做三桶平滑后的上升代理标签；并非从压测控制端读取真实目标 QPS。A 留出上升段 MI/RTX 2326/2405 条，B 为 2059/1540 条。这个标签可能同时受调度策略、模型预测和服务能力影响，不适合直接作因果解释。
- 另外独立定义**低压**为调度特征中 `running<=4 && waiting<=4`，**高压**为 `waiting>=33`，其余为中压；这是输入压力代理，不使用目标耗时作分段，也不等同于压测端 QPS。低压与“真值 `<256ms`”的零点子集是两种不同口径。跨压力拟合使用相同时间留出、每节点只从窗口开始前的参数状态初始化，避免后续在线状态作为初始化泄漏留出时刻；与上升段分析的三起点拟合不同，优化结果不可直接当同一个优化器设置的参数比较。
- 基础公式见 `resource/NonLinearPrefillModelR.cpp`：`max(0, p7 + 1500 * [shape(L,p8)-shape(p0/320,p8)] + p9*total_prompt + p15*preceding_count)`，其中 `L=(running 及 waiting 线性项 + p16*running_elapsed_ms/1e6)/320`，`shape(x,k)=x+sqrt(x*x+k)`。拟合固定 v21 的约束（如 p7>=0、p8>=1e-8、p15>=1），不冻结 p7/p8/p16。脚本实现于 `AnalyzeLatencyPhaseLeastSquares.py`；抽样复算与日志 `base_prediction_before_ms` 最大差约 `5e-10 ms`，解析 Jacobian 与数值差分一致。
- 静态最小二乘分别最小化 `(prediction-target)^2`（raw）和 `(log1p(prediction)-log1p(target))^2`（log1p）；每节点从初始、中间和最终线上参数三处启动，取训练损失最小的一次。表中主结果为 log1p。**这不是非凸问题的全局最优性证明**；部分候选达到迭代上限，近共线特征导致参数不可辨识。
- “在线 base”是日志中逐样本更新前的基础模型预测；“在线 final”是同一时刻的综合预测（包含 residual）。两者是已发生在线轨迹上的观测，静态拟合则是训练段拟合后预测留出段。比较可识别静态解释能力，不能把静态模型差值直接解释为在线替换后的收益。
- MAE 是毫秒绝对误差；bias 是 `真值-预测`，正值表示低估。下文的零点/短延迟子集定义为真值 `<256ms`，不等于按输入特征定义的低压段。误差样本以最终结果时间归档，不等于调度时刻的即时可用信息。

## 核心问题：高低压参数能否互相泛化？

这里的“全局”使用全部训练压力样本；“低压”和“高压”各只用自身压力段训练。所有行都评估**相同的留出段**，故可以直接比较。主损失是与线上更接近的 log1p 平方最小二乘；每行均是节点独立拟合后按留出样本数加权。单位 ms。

| 窗口/硬件 | 低压训练/留出 n | 高压训练/留出 n | 全局拟合：低/高留出 MAE | 低压拟合：低/高留出 MAE | 高压拟合：低/高留出 MAE |
| --- | ---: | ---: | ---: | ---: | ---: |
| A MI308 | 1366/2359 | 8780/2693 | 231 / 13975 | 3865090 / 5565415755 | 297237 / 12766 |
| A RTX 5000 | 2697/1849 | 6196/2637 | 387 / 2860 | 400 / 14958986 | 4064 / 3001 |
| B MI308 | 14465/4182 | 23966/7229 | 64 / 11733 | 164 / 1055780 | 6258 / 10642 |
| B RTX 5000 | 13150/4171 | 18821/4411 | 308 / 1656 | 315 / 14732 | 9251 / 1689 |

上表的千万/十亿毫秒数是**无约束外推失控**，不是待处理请求实际运行了那么久。A MI 低压拟合在本区间的加权 MAE 也被一个极端节点拉到 3865090 ms；该节点之外的行为不能用这个均值概括。作为抗离群补充，节点逐一计算“低压拟合预测高压”相对“全局拟合预测高压”的 MAE 比值，其中位节点 A/B：MI 为 8.7/35.4 倍，RTX 为 7.3/1.8 倍。反向的“高压拟合预测低压”相对全局模型的节点中位倍数 MI 为 151/114，RTX 为 6.2/34。**两个方向均不存在稳定的参数互换泛化**，但 RTX 的 B 窗口低到高迁移明显比 A 好，不可概括为“两个硬件各有一套固定高低压参数”。

解释这组失败时必须看局部可辨识性：log1p 训练目标的 Jacobian 各列先归一化，再以相对奇异值 `1e-8` 判断局部秩。16 个有效参数中，MI 低压拟合缺秩节点 A/B 为 7/10、10/10；RTX 为 2/9、0/10（RTX 的最小奇异值中位也仅约 `3e-4/4e-4`，仍偏病态）。MI B 虽有 14465 条低压训练样本，却全部节点缺秩，说明**增加同分布低压样本数并不能自动补齐高压方向的信息**。高压拟合虽然局部可满秩，也没有零负载覆盖；其零点 p7 中位值可漂至 A MI 近 0、B MI 27792 ms，B RTX 8111 ms，因此高压向低压外推同样没有物理保障。A 的少数拟合达到迭代上限；上述结果不构成非凸全局最小值的证明。

再以原始毫秒平方损失重做同一全局/低压/高压最小二乘：A/B MI 全局模型在低压留出 MAE 为 550412/26488352 ms；低压模型在高压留出可达约 9.8e8/1.2e7 ms。RTX 低压模型对高压也达约 8.8e9/1.0e11 ms。raw 损失对长尾的优化放大了参数抵消和跨段外推问题，因此不能通过换回普通最小二乘来恢复参数一致性；主表保留 log1p 作为更稳定的比较口径。

**回答参数一致性：** 在现有训练支持集和 v21 参数化下，高低压分别拟合出的预测函数不具有可用的双向泛化；低压数据尤其无法确定 MI 的高压参数。但当前无法把低压参数数值差解释为硬件固有的参数改变：多组参数在低压上等价，某些参数方向根本没被数据约束。应以跨压预测函数和奇异值，而不是直接比较 p0-p16 的原始数值，判断是否一致。

## 剩余误差：缺特征还是公式形式？

为了检验“只要换现有特征的组合形式就能解决”，在相同压力划分和时间留出上增加两类静态候选：其一在 `L` 中加 waiting 平方、running×waiting、elapsed×waiting；其二加从已有计数推导的 decode-only 及其与 waiting/running 的交互。再用只读相同 14 个输入列、对 log1p 目标训练的 HistGradientBoostingRegressor 作为更灵活的公式容量对照（不是线上可用方案，不能外推树模型为生产性能）。高压留出 MAE 如下：

| 窗口/硬件 | 基础公式全局/高压专拟 | 队列交互全局/高压专拟 | decode 交互全局/高压专拟 | 同输入灵活回归 | 实际在线 base/final |
| --- | ---: | ---: | ---: | ---: | ---: |
| A MI308 | 13975 / 12766 | 15031 / 13927 | 12804 / 12215 | 14646 | 10711 / 3641 |
| A RTX 5000 | 2860 / 3001 | 2505 / 3226 | 2943 / 3122 | 12800 | 3398 / 1654 |
| B MI308 | 11733 / 10642 | 10917 / 9904 | 10927 / 10612 | 10018 | 11668 / 9416 |
| B RTX 5000 | 1656 / 1689 | 1755 / 1670 | 1670 / 1678 | 1760 | 2476 / 1678 |

队列交互在 B MI 高压专拟改善约 7%，但 A MI 恶化约 9%；decode 交互在 A MI 改善约 4%，B MI 几乎不变，RTX 也没有一致收益。A 的 decode 候选还有多个节点未达到优化器收敛条件。更灵活的同输入回归在 B MI 高压优于基础全局约 15%，但 A MI 反而略差，A RTX 极差，说明它对时间分布转移也敏感。这些实验**没有稳定支持一个仅重写现有特征组合的简单公式**；但尝试过的公式族和单个树模型当然不能排除所有可能公式。

高压专拟在训练集上的 MI MAE A/B 仍约 8290/11078 ms，留出为 12766/10642 ms；RTX 训练/留出为 2307/3001、1613/1689 ms。MI 不只是“低压参数外推失败”，在观察到的高压数据上，同一组静态参数也难以达到 RTX 的误差水平。可能原因至少有三类，现有日志无法唯一拆分：其一调度时缺少 decode 工作量、KV 状态、排队波次等因果状态；其二现有公式的加性/曲率结构不足；其三 master 与 agent 特征/目标时间错位、服务端行为或噪声使相同可见输入对应不同耗时。在线 final 在 A MI 高压把 MAE 从约 10.7 秒降到 3.6 秒，说明历史状态补偿有实际作用；B MI 仅从 11.7 秒降到 9.4 秒，仍有大量未解释误差，不能以 residual 已改善来证明基础公式足够。

**统一结论：** 已确证的是跨压参数不可辨识和外推失败；对于高压内部剩余误差，当前更应优先检验“缺少调度时刻可观测状态/样本时序错位”，而不是凭某个交互项的离线收益改生产公式。这个优先级来自现有公式扩展的反证与在线历史补偿的效果，**不是已证明缺特征的因果结论**。需要把真实 decode 剩余工作量、已排程 token 和请求/批次顺序与调度快照对齐后，做同一划分的嵌套特征消融；若它稳定降低 MI 高压留出误差且低压零点不坏，可判特征缺失；若同一完整特征下灵活且可外推的公式稳定更优，才判现有公式形式不足。

## 差异的机制线索与反证

### 压力和公式工作区间不同

- `running>=9` 的样本占比：MI A/B 为 24.8%/13.9%，RTX 为 0.1%/0.2%；running elapsed 均值 MI 为 2437/1744 ms，RTX 仅 26/33 ms。因此当前日志并不是在同样运行中负载下对比硬件。9 月历史 runtime 日志曾显示 MI/RTX 的 `max_num_seqs` 为 1024/64；**尚未核实本次两个窗口的运行配置**，不能把这个数字当本次实验的因果结论。
- 在线 p8 的节点中位数 MI A/B 约 895/922，RTX 约 0.29/0.25；MI 约 97.5%/99.4% 样本处于 `|L|<sqrt(p8)` 的近线性区域，RTX 约 27%/28%。同一非线性公式在两种架构上实际运行于不同曲率区域，这比“RTX 参数更一致”更符合已见数据；但仍不能确定是硬件造成，还是各自负载分布/训练轨迹造成。
- p15（此前请求数直接耗时项）在线更新触及下界的比例 MI A/B 为 40.8%/52.5%，RTX 为 1.7%/2.4%。这提示 MI 的直接计数项与其他队列/工作量项存在竞争或结构不匹配。仅放宽下界并不保证改进，也可能使零点或外推更差。

### 候选新特征：哪些能、哪些不能说

| 候选 | 正向证据 | 反向证据 / 目前结论 |

## 新公式可行性判断

当前已验证的候选只是给现有 `L` 增加线性前交互项，并未成功证明需要更换 `shape(L,p8)`。两窗口结果表明：

1. 纯粹改损失到 raw 毫秒平方会在 MI 跨阶段外推失控，不可采用。
2. 分别训练高/低压力参数没有稳定提升留出上升段，并损害低压，不是可直接部署的双模型方案。
3. `decode_only×waiting` 的 MI 改善值得追踪，但其近乎完全共线、RTX 反向和参数不稳定，尚不构成可靠新公式。
4. 在线 final 明显优于静态基础公式，说明动态 residual 吸收了部分状态变化；但它也可能掩盖基础公式缺失项。用逐样本综合误差反推基础模型优劣必须拆出 base 与 residual，不能把 residual 的改善归功于基础参数更新。

**当前判定：无可上线的新特征或新公式。** 也不能反向断言现有公式已足够：MI 在上升和高排队段仍有秒级系统误差。要判断缺的是公式形式、工作量特征还是更新机制，必须做以下可证伪实验。

## 后续取证与验收门槛（本报告不执行上线）

1. 在 master 决策时记录同一请求的版本化快照：调度时间、入队顺序、节点、running/waiting 各计数与 token、decode 剩余/已排程 token、running elapsed、基础参数及 residual 状态、最终 agent 耗时。只用决策当时可见的值训练，排除到达/完成后的信息泄漏；核实 A/B 窗口 `max_num_seqs` 和负载控制指令。
2. 用受控、两架构均覆盖的高低压及上升/下降/稳态段，保持请求长度和缓存命中分布可比；在节点与连续时间块双重留出上，先固定现有公式比较加入单项真实 decode 工作量后的 **条件增益**。报告 MAE、P95、低压零点、上升开始 0-30/30-60/60-120 秒误差，并检验特征对 waiting/running 的条件共线性。
3. 若真实 decode 工作量无稳健增益，再比较曲率函数、饱和/队列交互形式及零点约束；要求两窗口、两硬件的正反方向稳定，拟合收敛且外推有限。否则优先研究在线更新/样本权重，而不以离线训练误差选择新公式。
4. 在离线逐事件**完整复刻线上更新顺序**后，才比较现有 Adam、逐参数学习率和候选特征；必须单独报告基础模型与 residual 的贡献、参数路径、限幅率及低压漂移。离线通过后还需线上相同压力曲线的 A/B 或前后可比验证；本报告不视为已完成。
