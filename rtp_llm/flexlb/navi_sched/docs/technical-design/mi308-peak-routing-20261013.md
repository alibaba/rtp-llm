## 完成反馈与原生公式回放

### Master admission 与 Agent 完成时预测：不能混为同一时刻

本节追加于 2026-10-13。`AgentLatencyKernel::compute()` 在 prefill 完成后取得当时的 `snapshotBefore`，先用该快照计算 `prediction_before_ms`，随后才把**本条**样本交给 `recordSample()`。所以它虽是本条训练更新之前的预测，却不是 admission 时的预测；Master `final_execution_ms` 才是该批 admission 前用于调度的预测。这里的 `revision 差`是完成时 Agent `revision_before` 减 admission 时 Master `model_revision`；两端时间点相隔几十秒，不能直接称它为 Master 同时刻的同步滞后。

按原始日志中的**整数** `schedule_batch_id` 逐批联结 Master 决策与 Agent 样本，以下四组分别全部联上；早期从 JSON 再读大整数时曾发生浮点舍入，按舍入后的 ID 联结会虚假漏数，以下一律回到原始日志重算。`预测差`定义为 Agent 完成时预测减 Master admission 预测；基础项和 residual 项也用相同方向。表中 `实际/主/Agent` 是这批样本 admission 到 prefill 完成的均值，单位秒；`修订差`为中位数。

| admission 窗口 CST | 硬件与批次 | 实际/主/Agent | 修订差 | 预测差均值：基础 + residual |
|---|---:|---:|---:|---:|
| 04:35:20–30 | MI308，56 | 83.23/66.88/83.14 | 7 | +16.26 = +7.37 +8.89 |
| 04:36:20–30 | MI308，39 | 59.54/64.96/60.07 | 8 | -4.89 = -1.55 -3.34 |
| 04:35:20–30 | 5000，56 | 67.89/67.36/67.72 | 5 | +0.36 = -0.43 +0.79 |

## 离散优化器的直接反例

第三轮 `04:53:34` 快照的诊断探针被限流，剩余 **23 条全部是真实回放请求**；24 台节点全部是 cost 候选，线上把 23 条全给 MI308 `11.225.199.135`。按原生 `CostSchedulerKernelInternal::forwardDiscrete()` 对**同一快照**核算，先只保留这 23 条 `cost_selected` 请求及对应 `node_matches`，使用快照中的节点、模型、`lambda=0.5`、token normalization power `0`、concavity `0`。`目标函数`是调度器内部待最小化的成本，数值越低越好；**它不是实际延迟，也不是最终误差率**。`单步改进`只迁移其中一个请求，`单节点候选`把全部 23 条给同一台 L20 `215.73.59.29`，`轮流分配`按 24 个节点索引循环分配这 23 条，是固定快照反事实，不是上线随机调度。

| 方案 | 目标函数数值 | 相对记录方案 |
|---|---:|---:|
| 线上记录的全 MI308 分配：快照原值 | 26266.098 | 基准 |
| 同分配由本地原生函数重算 | 26239.997 | 与线上差约 0.10% |
| 只改一个请求的最佳迁移 | 25517.144 | 低约 2.8% |
| 按 24 台节点索引轮流分配 23 条 | 21796.254 | 低约 16.9% |
| 全部给同一台 L20 的候选 | 20923.310 | 低约 20.3% |

独立负对照：在另一个 04:49:45 快照中，记录方案约 `34365.3`，24 台轮流分配约 `34872.0`，后者更差；不能因为上表就把随机/均分调度称为整体更优。04:53:54 快照记录方案约 `31119.0`，最佳单节点候选约 `30445.7`，差距小于上表。旧版采样快照中，线上与同分配本地重算有不足 `0.3%` 的差异，主要限制是 replay 重建的节点运行时间与原批次不完全一致；因此上表的 `0.10%` 是交叉校验而非 bitwise 一致，不能拿极小差异排序。当前工作树已有**未提交、未发布**的离散细化候选代码；同一过滤输入离线得到 `22173.253`、4096 次评估、8 次迁移，较原版成本降低约 `15.5%`，但无线上时间预算下耗时约 `32 ms`，而候选在线额外预算上限为 `2 ms`。这仅证明候选方向有效，不证明已上线、在线耗时可接受或真实延迟改善。

**统一结论与边界：**MI308 峰顶的实际“坑”是请求第一次执行前队列提前排空：当前可调度入口下降及 Master 阶段性减配减少入队，旧 decode cohort 随年龄增长而集中释放更多槽位，二者叠加；MI308 在本联合配置下的长占槽时间使它早于 5000 出现明显下陷。Master 对同批请求的 admission 预测先低估后高估；按原公式、真实 revision 和固定同批输入逐项重算，Master/Agent 两时点预测差主要是样本等待期间基础参数与 residual 参数改变，不是同版本公式不一致或入队特征细微不同。训练标签要等 prefill 完成才可更新，这种反馈对旧 decode 波次的未来释放没有提前可见性。Master 离散分配还存在经原生目标函数验证的次优反例，是独立的调度放大因素；未通过改路由的线上实测，不能把它的静态成本改善称为真实延迟收益。现有 P18 原生回算未解决 MI308 峰段误差；缺少逐请求在线 decode 进度分布对未来释放率的前瞻性验证，也未独立拆开硬件与 512/64 并发配置的因果贡献。后续方案必须以同样本在线 admission 指标和受控真实流量验证，不能把离线拟合或完成时 Agent 精度当最终效果。

### 低压退化与零等待门控

全段 MAE 会掩盖低压退化，因此在上文三方原始日志齐备的**同一批测试样本**上，按测试轮 Master admission `waiting_batch_size` 的四分位拆开。这里“低压档”仅指该测试轮 waiting 的最低 25%，两轮和两架构的数值边界并不相同；`waiting` 为 0 时表示入队时无待执行请求，并非 GPU 上没有 decode。`原版`是当时实际 Master 预测，`年龄+token`是上述冻结残差校正，`零等待门控`只在预测时把 `waiting=0` 的校正量设为 0，其余样本保持校正量不变；模型训练样本、Ridge 系数、原预测和流量均相同，**不是**另做参数寻优。MAE 单位秒，括号为该档测试批数。

| 硬件、训练轮 → 测试轮 | 最低 waiting 四分位边界 | 全段原版 / 年龄+token / 零等待门控 MAE | 最低档原版 / 年龄+token / 零等待门控 MAE |
|---|---:|---:|---:|
| MI308，第二轮 → 第三轮 | `0–<136` | 15.378 / 4.674 / 4.408 | 10.824 / 4.740 / 3.673 (263) |
| MI308，第三轮 → 第二轮 | `0–<128` | 12.572 / 5.647 / 4.839 | 7.853 / **8.287** / 5.013 (662) |
| 5000，第二轮 → 第三轮 | `0–<1` | 2.451 / 1.879 / 1.642 | **0.018** / 1.004 / 0.018 (129) |
| 5000，第三轮 → 第二轮 | `0–<49.75` | 3.145 / 2.437 / 2.292 | 1.726 / **1.867** / 1.288 (617) |

高压三档的改善不能抵消“低压本来准确却被校正搞坏”的上线风险，尤其 5000 最低档原版仅约 `18ms` MAE，直接校正变成 `1004ms`。`waiting=0` 只说明快照中没有先前等待项，**不保证**新请求不会被正在运行的 decode 挡住；门控是保留这批原预测的保守规则，并非队列代价必为零的物理定理。四组的全段与最低档 MAE 均好于未门控，但仍未证明 waiting 大于 0 的所有局部窗口不退化。额外试过把训练样本也限制在 `waiting>0`：MI308 两方向全段为 `4.791/4.856s`，不比上述只在预测时门控的 `4.408/4.839s` 稳定；5000 为 `1.610/2.116s`。平滑门槛 8、32、64 也离线扫过，但本节不据此选上线常数。表内的门控仅作用于**实验性线性校正量**，不能未经原生模型和端到端验证就映射为线上 residual 参数。

把同一个零等待门控叠到上一节按真实完成时间更新的**第三轮因果回算**，MI308 新标签权重 1/10 的 MAE 为 `4.381/4.347s`，相对未门控因果回算 `4.637/4.545s`；5000 为 `1.643/1.667s`，相对 `1.875/1.879s`。因此低压保护的收益不只出现在冻结模型，但仍是原流量下的离线后处理，不能代替实际 Master 发布、路由反馈和线上同窗验证。

### 从零开始的 RLS 与标签延迟反证

上述跨轮实验都先用另一轮标签训练校正器。为了检验冷启动，另把每轮各自从**全零校正参数**开始，RLS 逆协方差初值为 `I/ridge`，按 Master 调度时间预测，只在对应 Agent 完成标签到达后按 Sherman–Morrison 秩一公式更新；零 waiting 仍不加校正。输入含原 Master 预测、waiting/preceding/running、年龄六桶和已生成 token，各用硬件并发上限及固定 token 单位缩放，没有用本轮样本均值标准化；这里依然是原 Master 预测上的**独立线性残差诊断**，不是生产 19 参数模型的 RLS 化。`遗忘因子`每收到一条标签作用一次；`1` 不遗忘，`0.99` 给旧标签逐次衰减。`oracle 立即反馈`故意在每条请求调度后立刻交付其未来真实误差，只用于衡量标签等待的影响，在线**不可能实现**。

| 硬件、波形 | 测试批数 | 原 Master MAE | 冷启动 RLS：遗忘 1 / 0.99 MAE | oracle 立即反馈 MAE |
|---|---:|---:|---:|---:|
| MI308，第二轮 | 2682 | 12.572 | 12.842 / 11.529 | 5.035 |
| MI308，第三轮 | 1056 | 15.378 | 15.704 / 14.891 | 5.241 |
| 5000，第二轮 | 2468 | 3.145 | 2.564 / 2.396 | 1.930 |
| 5000，第三轮 | 537 | 2.451 | 2.721 / 2.522 | 2.058 |

表中 RLS/立即反馈均取 `ridge=1`，其它条件及测试批次相同。MI308 第二/三轮头 60 秒原 Master MAE 为 `31.834/21.100s`，真实延迟反馈且遗忘 `0.99` 的 RLS 仍为 `30.909/21.063s`，而不可能的立即反馈为 `7.740/3.801s`。这说明**在这组冷启动线性校正中**，约几十秒后才知道 prefill 标签是实时跟随收益受限的主要因素；预训练跨轮的 `4–5s` 好结果不能直接变成冷启动默认值，也不能靠“求逆更快”消除标签迟到。它不排除利用调度前已知状态构造更强的非学习物理先验，或保留跨重启状态改善冷启动。

数值反证同样重要：遗忘 `0.95` 时 MI308 `ridge=1` 的第二/三轮 MAE 恶化为 `23.141/16.203s`；5000 第二轮的朴素逆协方差更新出现非正分母并停止，遗忘 `0.99` 时虽能完成，但 5000 第二轮最大协方差特征值约 `9.5e9`、单步最大参数变化约 `131.7`。这不是“RLS 数学上必然不稳定”的结论，而是本诊断实现对长流、共线年龄桶及强遗忘**没有**生产级数值保护的直接证据。秩一更新另用 12 维、100 步的直接加权 Ridge 解作独立正向验算，含共线输入和 `0.99` 遗忘共 3 项测试通过；它只验证短序列公式，不能覆盖长流稳定性。未做稳定 Cholesky/QR 更新、持续正则、重置策略、计算耗时和真实服务线程基准，不得打包成“终极解法”。

### 冷启动事件顺序与长流数值独立复核

另用 `/home/zq103303/tmp/audit_navi_decode_age_cold_stream.py` 从原始三方联结样本重新载入两个硬件，各自并行审计。这里 `完成延迟` 是 Agent 完成事件时刻减 Master 调度时刻，和 prefill 标签 `target_ms` 不同；二者相差还包含调度到 Agent admission 的时间。第二/三轮 MI308 分别为 `2682/1056` 批，5000 为 `2468/537` 批，没有重复 Agent 完成键，也没有完成早于调度、年龄快照来自未来或快照陈旧达到 10 秒的入选样本。完成延迟中位数 MI308 为 `51.119/44.506s`，5000 为 `59.692/49.437s`；完成延迟减标签的中位数为 `0.091/0.091s`、`0.054/0.059s`。这些数只覆盖入选批次，不能代表被拒绝请求。最后一次可见调度之后才完成的入选批次 MI308 为 `295/221`、5000 为 `182/116`；在线回算只在调度时消费**之前**已完成标签，故末尾的 `updates` 少于测试批数是预期行为，不是丢标签。

以同一事件顺序，独立维护指数加权正规方程 `A <- lambda*A + x*x^T`、`b <- lambda*b + x*y`，每 100 次已完成样本更新用直接线性求解与 Sherman–Morrison RLS 权重比较。`lambda=1` 时四组最大权重差均低于 `1.2e-10`；`0.99` 时最大为 `4.9e-8`，支持前述回算的事件与公式实现。`0.95` 时 5000 第二轮在第 `2241` 次更新之后失效，失效前直接方程条件数曾达到约 `1.6e51`、两种求解权重差超过 `2e9`；在如此病态的矩阵上直接求解也不是真值 oracle，不能据此单独断言哪一个数值算法更准确。这里只能确定当前**无持续正则保护**的强遗忘实现不可上线；这不是一个完整的生产 RLS 基准。按本机 NumPy 诊断脚本，约 2400 次更新与每 100 步一次直接求解用了约 `0.05s`，不含载入日志、Master 通信、生产锁竞争或每步求解，不能外推为线上微秒级成本。

### 多时间尺度释放曲线与同批 prefill 预测

固定 60 秒释放数不能当作恒定速率外推：第三轮训练、第二轮测试时，第二轮最初 60 秒的 132 个 MI308 batch 用此简式估首槽等待，真实均值 `95.95s`、预测均值 `207.66s`，平均绝对误差 `112.83s`。另有 80 批在后续采样缺口无 60 秒前快照，不能把全部 212 批都称作初段。于是改用训练轮**旧占槽请求**在 `15/30/45/60/75/90/120/150/180/240s` 内释放的经验比例：每个年龄桶、每个时间尺度都只统计该训练时点之后有完整日志覆盖的请求，分母为训练时点该桶旧占槽数，分子为其在该尺度内释放数。发现压测结束的 `finish_requests` 会释放槽位后，进一步要求训练样本的整个 240 秒观察窗在该节点首个非 `output_stop` 释放前至少 30 秒结束；严格口径下训练第二/三轮分别有 MI308 `545/540` 个节点时点，5000 `422/385` 个。测试仍严格用另一轮调度前最多 10 秒的年龄快照，不取测试轮未来释放标签。设各桶数量为 `n_i`、训练得出的释放比例为 `p_i(t)`，则预期释放曲线 `R(t)=sum_i n_i p_i(t)`；在 `R(t)` 首次达到 Master 的 `waiting_batch_size+1` 时线性插值得到首槽等待。若 240 秒内仍达不到，保留原 Master 预测，不外推。
