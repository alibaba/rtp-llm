# 类与方法的实现规范

把明确的行为落实为容易理解、容易修改、能够验证的代码。降低状态、依赖、控制流和维护成本；代码行数或类数只是结果，不是优化目标。

## 1. 接住整体契约，限定本次实现范围

与 [workflow-first-design](../workflow-first-design/SKILL.md) 共用行为契约：整体层决定流程、责任边界与跨组件协议，本层落实到类、字段、方法和测试。契约已有于对话、代码或文档时直接复用，不另做整套设计材料。

局部任务先核对输入、预期行为、相关约束和责任类，即可实施。涉及状态或副作用时，再核对失败动作、生效点和清理责任。简单修改按需缩减，不机械生成表格或测试。

以下发现需要回到整体层调整受影响的契约：必须改变策略语义、转移跨组件状态所有权、改变公共协议，或突破系统性能约束。保持契约的字段组织、私有方法拆分、局部算法和封装选择由本层自行决定。不得为了实现方便改变等待、重试、降级、公平性或性能要求。

反例持续导致新增标志、回调和特例时，先检查被推翻的假设及责任边界；不能用补丁掩盖设计缺口，也不因局部缺陷重写系统。只有未决业务含义会改变方案且无法从上下文确认时才询问用户；这不是新增审批流程。

## 实现过程中执行边界检查

新增或改变公共方法、成员状态、跨组件回调前，对照已确定的契约核对：本类是否有权做这个
决定，参数是否授予了多余的访问能力，状态是否已有权威来源，成功和失败后的责任是否明确。
不能以“后续 review 再收敛”为由先加入越界入口；也不能用窄接口包装完整上层对象关系。

第一条正常路径及关键失败路径打通后、复制到其他角色或模式之前，沿真实调用者检查到
副作用与清理出口。必须确认：

- 结果对象没有夹带等待、重试或取消决策；底层没有通过对象导航寻找上层流程负责人。
- 同一有效性没有新增独立写入者；回调使用精确操作身份，旧通知与晚到资源仍有人处理。
- 交接失败时能直接指出清理者；替代入口接入后，同范围失去用途的旧入口和中间状态同步删除。

任何一项不成立，先修正受影响的契约与实现，再扩展后续路径；不要继续增加标志、适配层或
补偿分支掩盖问题。结构检查靠真实调用链，行为保证用必要的测试验证；编译通过、UT 通过、
包依赖合规和代码量下降都不能替代此检查。不要求另写检查报告或重复填写设计材料。

## 2. 用真实路径确定修改位置

阅读实际入口、关键调用方、目标类、相关依赖和测试，确认当前代码与运行环境版本。只追踪与当前假设相关的路径，不无目标遍历系统。

审核目标类时完整读取类、直接调用者与实际被调实现，长文件分段读取，截断输出不算已读完。
核对普通调用之外的方法引用、框架入口、反射、序列化与可替换实现，不按检索不到调用就判死代码。
只要求审核时输出证据与建议，不直接改生产逻辑；局部发现跨组件协议问题时转到设计层处理。

区分观察到的事实、解释和待验证假设。代码中存在某个机制不等于运行时执行了它，错误表象不等于根因。优先选择能区分不同解释的测试、日志或实验；回归问题必要时对照隔离基线。部署、版本或工作区变化后重新确认相关证据。

确定每项修改如何对应需求或必要依赖，再写代码。沿用项目已有的错误、配置、资源管理和扩展约定，不顺手引入框架或额外能力。

## 3. 为类确定职责和不变量

对本次新增或实质调整的类，能回答：它代表什么、负责什么、对外保证什么、依赖谁、何时创建和结束。优先复用已有责任组件，不机械地为每个阶段创建一个类。

- 数据对象承载明确粒度的事实或结果；维护自身数据约束，不暗中登记资源、调度任务或发起网络请求。
- 行为对象执行语义完整的操作；方法名和返回值必须体现实际副作用与保证，不能让“选择”暗含调用方不知道的生命周期责任。
- 协调对象处理必要的多步交接和部分成功；只有独立的跨组件责任确实存在时才引入，不能只是转调或搬运字段。

以上是职责检查，不要求固定分成三类。对象持有资源时明确关闭或释放契约；不能通过换一个 Result、Context、Manager、Execution 名称掩盖混合职责。

逐个核对生产构造点和消费点：调用方应能从类型与明确状态知道允许的操作，
不应追溯构造函数或靠空字段辨认用途。重点检查以下误合并信号：

- 同一个类型承担选中结果、提交凭据、结束原因与历史记录，各用途只有少数字段有效。
- 所有实例实现资源接口，但某些用途没有资源，接口方法只能报错或返回无意义的空值。
- equals/hashCode 根据可选字段或构造方式，在身份语义与值语义之间切换。
- 已有结果容器表达失败，负载对象又复制同一份状态、阻塞原因与诊断。
- 纯结果读取外部实时状态并决定重试或释放。资源持有对象可以提供回滚，但应有明确契约，
  不能只因能取得资源引用，就把特定角色的释放策略塞进通用选择结果的静态方法。

这些信号用于追查契约，不要求机械拆类。反例检查是：只拿到一个合法实例，
不知道它由哪个调用者构造，能否正确使用其公开接口？

继承仅用于稳定的可替换关系：子类必须遵守父类的输入、输出、失败和生命周期约束。仅为复用字段、资源记账或分支代码时，先考虑组合或已有公共能力。基类不应判断子类类型、承载大量可选字段，或要求子类以空实现绕过契约。不为一次调用创建无实际替换需求的接口体系。

## 4. 把字段归属和生命周期落实到代码

**职责合理性优先于实现方便。** 不能因为某对象在调用链中容易取得，就把回调、服务引用或
可变执行状态塞进只负责身份的对象。新增字段前先说明它属于谁、由谁修改、何时释放；
优先放在已有的资源或操作记录中，不为少传一个参数改变对象职责，也不机械地新增包装类。
例如仅表示登记身份的 RequestRegistration 不应顺便保存通知接收器；接收器可由 Endpoint
的资源记录持有。锁外发送或异步处理需要的信息，应在生成通知时连同精确登记一起捕获，
不能稍后按 requestId 查询最新记录，否则旧通知可能误用新登记的接收器。
此例约束的是身份与执行职责的区分，不要求把本来就负责资源生命周期的对象拆成纯 ID。

新增或修改关联字段时，按 [单向关联规范](../workflow-first-design/SKILL.md#优先单向关联减少双向依赖)
检查是否形成“管理者持有记录、记录又持有管理者”。只取固定数据时传入必要值；管理者已有
足够信息时由其执行状态检查和清理。不要仅将具体类型改成接口或回调就宣称消除了反向持有，
也不要为了删除引用增加新的协调层。保留必要双向关联时，在实际生命周期位置明确用途和解除责任。
调整后检查直接字段及回调捕获，验证身份校验、取消失效、锁外通知和无法交付资源的回滚没有丢失。

涉及重复数据或状态调整时，用紧凑的字段归属表核对；简单字段修改无需填表：

| 字段／事实 | 粒度与含义 | 唯一权威持有者与修改入口 | 读取者／派生副本 | 生效、失效与清理 |
| ---------- | ---------- | ------------------------ | ---------------- | ---------------- |

- 区分请求、一次尝试、节点和一次操作的身份，不能让旧尝试的字段参与新尝试判断。
- 能从可靠现有事实得到的值，通常不另维护一份可变状态。快照、缓存和估算可以存在，但要明确采样时点、更新或失效规则，以及是否计入同一份资源影响。
- 不因字段相似就合并不同粒度的事实，也不在多个结果对象中复制相同生命周期的字段。判断依据是职责和约束。
- 构造完成时尽量形成合法对象。确需分阶段构建时，限制未完成对象的可见范围，避免调用方依赖 setter 顺序、非空字段或多个布尔值猜测阶段。
- 选择明确的修改入口，避免公开可变集合或通过 getter 绕过不变量。不可变快照与活状态引用须有清楚区别。
- 名称沿用领域术语，同一概念同名。handle、lease 等名称只有在语义确实匹配时使用，并解释它代表的具体权利和责任。

对重要 map、set、标志和 token 逐项查创建、读写、清除与取消后有效性。先问决策实际需要什么，
不从现有字段倒推必要性；区分业务事实、异步未完成工作、排序索引与性能缓存。可推导字段还需
核算扫描和分配成本。队列已移除不代表异步任务结束，不能删除晚到资源的接收和清理责任。

检查一次调用前写成员、finally 清空、回调再读取成员的临时传参方式，以及低频诊断为复用视图
另设缓存、版本和二次写回的情况。优先使用局部参数或已有事实，但保留有实测价值的缓存和索引。

### 状态字段与枚举的实现检查

涉及状态或阶段的实现，先按 [设计规范的状态职责边界](../workflow-first-design/SKILL.md#状态与阶段按职责收敛)
确定对象、粒度和权威来源；不要从类名出发各建一个 `State` 或 `Phase`。

- 同义状态复用现有表达；从已有字段可直接判断的事实，优先提供具体布尔查询，
  不额外维护枚举字段或仅供诊断的同义类型。必要的采样快照保留明确的采样时点。
- 状态转移在负责组件的实际提交位置集中维护，校验准确身份与原状态；调用者不通过连续
  setter 或多处标志拼装转移。跨异步边界仍需核对最新状态，不能用一次旧快照替代。
- 类型名和字段名说明对象与用途；只有外层类型已经清楚限定含义时才使用内部 `State/Phase`。
  枚举值按同一维度命名，区分当前阶段、历史事实和不确定观察，不用注释掩盖混合含义。
- 对外查询状态从权威事实生成，不维护另一份可独立改写的进度；映射、最终结果优先级和
  清理未结束时的行为集中表达。协议必须转换时保留边界语义，不逐层复制同义枚举。
- 两值枚举与 boolean 按调用语义选择；不为减少类型丢掉原因、模式或命令含义，也不为
  强调类型把一个真假查询包装为新枚举。替换后删除失效的转换、字段、入口与对应夹具。

## 5. 让方法和接口表达完整语义

方法应完成一个调用方能够解释的操作。必要的连续操作可以放在同一方法中，不为了行数拆成大量依赖隐含顺序的小函数。

沿调用方核对 decide/select 是否还投递、移除或取消，NO_ACTION 是否仅表示没有后续等待。
追踪 null/boolean 的各个含义，不机械换成枚举。返回 Runnable 时区分启动操作与订阅结果，
明确 Future 创建、启动、订阅的时点及已完成 Future 的同步回调。子类只改变一步却复制整条流程
与错误优先级时，优先收敛共同动作。清理参数已能从目标记录得出时，不让上游重复指定资源细节。

- 明确前置条件、输入身份、返回事实、状态变化和异常后的保证；返回“成功”到底意味着计算完成、登记成功、发布还是执行完成。
- 纯计算只接收必要信息，避免为了方便传入整个可变 Context；执行副作用的入口要清楚，但不强制计算与登记分开到破坏原子性。
- 只向上暴露会改变调用方决策的结果。局部版本冲突、内部代际等可在责任组件内消化，诊断信息按需保留；不要把所有底层细节变成上层状态。
- 区分确定未发生、已发生、结果未知。异常或通知失败不能自动解释为安全重放；遵守整体契约中的等待、清理和重试决定权。
- 避免含义不明的布尔参数、重复重载、转调包装和不一致的错误通道。增加结果类型或参数对象应解决实际歧义，而非仅为形式统一。
- 依赖沿责任边界传递。底层不应通过回调、全局对象或反向引用偷偷决定整个流程的策略。

类型按表达的业务概念归属，不按“底层也需要几个字段”归属。底层定义窄接口并由上层实现
可以合理，但不能完整复刻上层 Context、路由、调度器和响应状态来绕过模块依赖限制。
核对参数、字段、返回值、回调读取和强转，确认底层只取得完成操作所需的事实或能力。
资源事件围绕精确登记表达事实，由业务负责人解释整体影响，不能简化成只有业务 ID。
事件逐字段复制成另一类型时，应有明确的语义转换或隔离目的，否则优先复用已有表达。

内部事实优先生成协议表示，避免保存可变响应，再从响应反推业务身份和决策输入。
底层报告准确原因与证据，由负责层决定等待或重试，协议边界再映射错误码；
避免先编码错误、再遍历错误码反推原因。确有相同契约时可以复用类型，不要求每层各建 DTO。
选择时需要冻结的身份、代际和估算仍须保留，不能用返回时读取实时状态替代历史事实。

校验按约束的负责对象收拢，不在每一层重复防御：

审核同时检索 requireNonNull、checkState、checkArgument 及等价分支，按非空、身份、阶段、
容量、锁与结果契约归组，检查工厂到构造器、包装到实现和父子类的连续校验，不能只比较文本。

- 沿实际调用检查同一个值在哪里已验证，以及到使用点之间是否可变、解锁、执行外部回调或异步交接。
  不可变对象的构造约束可供后续代码依赖；独立公开入口仍须覆盖自己的输入路径。
- 工厂直接调用有完整约束的构造器、包装层转交给已有校验的实现、JDK API 已明确拒绝空参数时，
  优先保留一个负责位置。先确认真实 API 契约，避免同时重复 `requireNonNull`、条件判断和防御性复制。
- 同一把锁内被更强条件完全包含的判断可以合并；不要把更新前后的条件、精确资源身份和容量转移结果
  当成重复。检查中含 `add`、`remove`、CAS 等实际动作时，不能连同断言一起误删状态变化。
- 校验必须发生在它保护的副作用之前；不能因下层也会检查，就先绑定 Future、登记资源或停止接纳再报错。
  移动校验还要核对异常类型、错误优先级和同步拒绝时机；需要改变时明确契约并验证，不能只证明仍会抛异常。

## 6. 在操作边界完成状态与资源责任

把整体设计规定的取得、交接、释放落实到确定的代码位置。检查正常路径和最关键的异常路径：每一步修改谁的状态，下一步失败由谁清理，何时可以安全开始替代操作。

- 取得资源后、尚未放入主记录前发生异常，也必须有释放负责人。责任交接以约定的生效点为准，不能根据字段非空猜测。
- 多资源部分成功时遵守契约规定的保留或撤销范围；需要整体撤销时清理全部实际取得的资源，不硬编码最先失败的组件。
- 区分允许重试与已经能够重试。撤销、临时任务退出和资源清理达到约定条件后才能重放；保留规定的请求身份、优先级、截止时间及完成对象。
- 释放须针对精确操作身份；重复释放或晚到回调不能影响其他请求和新尝试。幂等保护不替代明确的清理责任。
- 枚举清理候选与实际删除分离时，候选只提供待检查对象；提交删除前核对精确记录及最新活动时间。
  外部保留查询在资源锁外执行，查询期间的替换、释放再登记和新反馈不能让旧候选删除新记录。
- 一个资源释放失败不应阻断其他独立资源的清理。保留未完成责任和错误，不能把返回失败当成资源已回收，也不能假装成功回队。

优先使用语言和项目现有的作用域清理机制。只有跨调用、异步或生命周期需要时才引入持久管理对象，不以形式统一增加线程、回调和状态机。

## 7. 把并发与性能约束落实到操作范围

指出需要原子的判断与变化，以及其他调用何时能够看到结果，再选最简单的正确同步方式。不预设必须加锁或无锁。

- 检查锁覆盖的数据、锁顺序和持锁调用链。网络、外部回调、阻塞等待和昂贵计算原则上在锁外；必要例外给出依据。
- 用具体交错核对检查与更新、失效与提交、取消与清理、旧回调与新尝试、释放与等待登记。不能仅以有锁、有版本或有原子变量声称整体线程安全。
- 局部变化优先局部更新；重算前核对依赖，区分复用结果重新比较与重新执行昂贵计算。不要为局部冲突默认全表扫描或全局串行化。
- 核对热路径新增的分配、扫描、锁竞争、排队、通知和重试。无锁方案也要解释可见性、重试成本和进展保证；预算和阈值应有依据。

同一持锁调用 prepare 后立即 commit，却暴露版本、过期结果和重试协议时，先确认是否真的跨越
解锁或异步边界。性能结论写清扫描对象、规模、重复次数、锁持有工作和分配；复用索引前核对角色、
代际、生命周期及统计口径，不能用一个廉价计数代替不同事实，未实测只报告成本推断。

实现无法满足整体约束时，带着具体证据返回整体层调整受影响的方案，不静默削弱保证或新增常量掩盖矛盾。

## 8. 用测试证明行为，按环境验证性能

从行为契约推导测试，优先覆盖最可能推翻实现的边界，观察可见结果与实际副作用，避免逐行复刻实现或只断言 mock 被调用。

纯逻辑适合单测；所有权交接和通知链需要组件或集成验证；运行环境决定行为时沿真实入口验证。Mock 不能替代正在验证的关键机制。局部单测通过不能代替多组件流程验收。

涉及资源、异步或重试时，按改动风险覆盖部分成功、重复调用、取消或超时、晚到回调及关键竞态。尽量用可控同步构造交错，避免靠随机等待证明并发正确。简单、可逆且低影响的修改不为了形式新增测试。

接口宣称通用时，用实际支持的不同角色、模式与阶段验证，不只验证主要角色的正常路径。
提交前取消不能代替提交成功后的取消测试；通用取消不得暗中假设某个角色必然存在。
只支持特定路径时明确限制入口，确需通用时由契约确定目标和行为，不持续补空值分支。
等待保护调整还须保留同级与更高优先级竞争、取消立即失效、晚到资源接收或回滚等实际约束。

失败测试先判断契约是否改变、实现是否回归或环境是否异常，必要时对照基线。保留仍有效的行为断言，不改期望迁就实现。

生命周期重构先保存基线、运行相关行为 UT，再修改复验。竞态测试用屏障或锁存器固定暂停点、
另一线程动作和恢复后的结果，检查资源余额、响应次数、有限重试与旧身份隔离，不只断言私有字段。
读测试应核对安排和断言，测试名称不能证明覆盖窗口。契约明确改变时说明哪些旧断言失去前提、
剩余保证由哪些测试覆盖，不能批量删除测试掩盖未迁完的调用链。

用户指定 UT、perf test 或执行环境时按要求完成，不能以本地替代环境通过宣称完成。性能对比核对代码版本、配置、负载、预热和统计窗口，报告相关的吞吐、尾延迟与错误。不得放宽门槛、换负载或隐去异常；单次达标不能证明没有回退。

区分读过源码、实际运行通过和真实环境验证；记录被替代的依赖及证据限制。检查通过后，仅因新变化、失败或未解决风险扩大验证，避免无理由重复运行。

## 9. 随调用迁移清理旧实现，检查最终 diff

方案替换时给出具体的保留、合并、删除项及理由。迁移调用后清理失去用途的入口、字段、重载、包装、重复登记或回滚、配置、mock、测试夹具和旧术语；仍有效的行为测试保留。确需过渡路径时遵循整体方案的退出条件。

UT 专用入口优先删除，断言改走真实入口、已有快照或夹具，不只降可见性或搬成包装层。
审核删减时检查无实际替换用途的参数、只生成转调闭包的工厂和重复任务收尾；迁移整段方法、
改名、扩大锁或吞异常均不能作为复杂度下降的证据。

交付前通读最终 diff，确认主流程能直接看出触发、决策、执行和结束；新增抽象确有职责，旧机制已删除，没有覆盖用户的其他工作。注释解释必要约束和非显然取舍，不替难以阅读的控制流辩护。

报告实际改变的行为、关键类的责任变化、执行过的验证及未完成项。复杂任务将证据回传整体层完成集成验收；只完成类实现或单测时，不把整体任务标为完成。

每条代码审核意见说明触发场景、具体位置、根因、改后的事实来源、删除项、保留项和 UT，
区分源码确认、交错推演与实际复现。拟议 API 标为示意，不伪装成现有实现；不只给“类太大”的结论。
