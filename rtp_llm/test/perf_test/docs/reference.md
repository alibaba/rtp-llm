# Unified performance test reference

`tools/perf_test` is the only supported performance-test command. Every new
run receives exactly one JSON config with these top-level fields:
`schema_version`, `model`, `engine`, `workload`, `execution`, `output`,
`regression`, and `publish`. Unknown fields, includes, interpolation, secret
values, and undeclared engine arguments are rejected.

## Capability matrix

| Mode | Backend | run | resume | profile | report |
| --- | --- | --- | --- | --- | --- |
| prefill | local | yes | yes | yes | yes |
| decode | local | yes | no | no | generated by run |

`--skip-test --run-dir=...` is the offline prefill `report` alias for local
runs. It rejects decode and any action other than `report`.

Prefill uses cache grids. Decode supports fixed input/global-batch grids,
materialized distributions, and bounded target-TPOT search with one scalar
`output_length`. New runs accept only `execution.backend=local`. Historical
schema-v2 results with `backend=aone` and their execution plans remain readable
as data; the public CLI cannot run, resume, profile, or report those plans.

## Commands

Preview a local prefill run without filesystem or engine side effects:

```bash
./tools/perf_test --mode=prefill --action=run --config=rtp_llm/test/perf_test/examples/prefill_local.json --dry-run
```

Regenerate only derived charts and formula analysis from a completed prefill run:

```bash
./tools/perf_test --mode=prefill --skip-test --run-dir=perf_test_results/prefill-run
```

Preview a local decode run:

```bash
./tools/perf_test --mode=decode --action=run --config=rtp_llm/test/perf_test/examples/decode_grid_local.json --dry-run
```

`run` accepts `--config`. Follow-up actions accept `--run-dir` and reject config
overrides. Only prefill profile accepts `--cases`; omitting it selects every
planned case. Prefill run and resume write the offline charts and formula fit
report after formal results are finalized.

## Run directory

Each non-dry run creates one immutable directory below `output.result_root`:

```text
source_config.json
resolved_config.json
execution_plan.json
manifest.json
workload/
checkpoints/
results/cases.jsonl                 # prefill case records (latest record wins)
results/cases/<case_id>.json       # decode case records
results/result.json
results/summary.json
reports/
profiles/
traces/
```

The execution plan is frozen before model startup. Mutable
JSON artifacts are written atomically, and one writer lock protects each run.
Case IDs derive from normalized case identity and remain stable across ordering
changes. Formal results use the versioned common envelope; prefill and decode
metrics remain distinct payloads.

Traffic-sampled prefill resolves its distribution file on the controller and
records the digest and sampling summary in `resolved_config.json`; the execution
plan contains frozen cases. Remote SSH hosts do not require the source file.
The accepted distribution can differ from the source due to bounds and batch
budget rejection; sampled lengths do not replay request arrivals.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | completed successfully |
| 2 | invalid CLI, config, or unsupported capability |
| 3 | invalid plan or unavailable resource |
| 4 | engine lifecycle failure |
| 5 | case failure or partial measurement |
| 6 | collection, report, regression, or required publisher failure |
| 130 / 143 | interrupt / termination signal |

## Manual SSH

The public SSH controller runs prefill and decode using an explicit host list.
It does not allocate machines. Prepare model/tokenizer paths, SSH access and
public build requirements on all hosts. See the benchmark guide for the YAML
controller config and local JSON workload contract.

```shell
python -m rtp_llm.test.perf_test.multi_node.multi_benchmark -c rtp_llm/test/perf_test/multi_node/prefill_ssh_example.yaml
```

Rank zero measures and finalizes results; other ranks serve the distributed
model. The controller owns startup, shutdown, and artifact collection. Public
execution needs neither `internal_source` nor private Bazel configurations.
Regression and publisher fields remain parsed for schema compatibility; the
public run entry does not compare baselines or publish results.
