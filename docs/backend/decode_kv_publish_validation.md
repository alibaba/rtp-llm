## 退出问题与 SDK 限制

上一轮 SDK794 完整包关闭 D 发布、关闭 KVCM 远端缓存、无 Consumer 时，普通 P 请求成功，1790 输入的 PD 请求自然 EOS 返回 37 token，输入/输出 IDs 与上述配套 SDK 源样本逐项一致。P 两 rank 及一个 D rank 正常退出，另一个 D rank 原始 waitpid 为 SIGABRT（signal 6）；父进程 0 不能覆盖此失败。

两个 SDK 作用域均出现过 D 关停阶段 DeepGEMM grid timeout、随后在 Tensor 释放路径报告 CUDA 错误并 SIGABRT。现有 DP2 fake 工作与各 rank 本地独立退出之间存在静态协议缺口；具体最后 kernel/collective 根因没有证明。没有已确认的新功能遗留 pin 或未排空 IO 造成该异常的证据，也没有完整计数可以排除所有资源问题。

**用户要求的真正原始代码对照尚待执行。** 已从不含我们改动的官方 `9115e23` 原样源码构建完整包，并逐一验证 8009 个源码 blob/mode、2150 个安装成员、SDK 和三份实际加载的原生库；不能将我们的 feature-off 包替代它。若该纯上游原包也复现，按用户明确要求，将退出问题与 SDK 限制一并记录，不再阻塞本批核心功能交付，不继续扩展诊断矩阵。

默认 SDK794 在旧轮次开启远端缓存的配置中于 P 就绪前报 `no kernel image is available for execution on the device`，没有发出请求。其 DSO 只有 sm103 cubin、无 PTX；已验证的配套 SDK1025 包含 sm100/sm103。新旧设备均为 aarch64，功能制品应按实际 CUDA 镜像及容器 ABI 核验，不按设备名称或会话重复构建。上述启动失败未捕获首个具体 kernel，仍需保留因果边界。无远端缓存模式的成功输出不能冒充旧 SDK 远端缓存路径通过。
