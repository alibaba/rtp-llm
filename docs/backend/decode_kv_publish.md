# Decode 完成后发布 KV 到 DRAM

该功能让分离部署的 Decode（D）在请求正常结束后，将已经计算完成的 KV 检查点发布到 PACE DRAM，供下一轮 Prefill（P）恢复。它默认关闭，仓库保留上游默认 SDK 和现有 Manager。开启功能使用已验证的配套 SDK `2026_10_25_15_21-cuda130.aarch64`，编译头文件、链接输入和运行库必须来自同一 SDK；不能只替换运行库。默认 SDK `2026_10_13_22_33-79404320` 单独验证编译和关闭态兼容。本次范围允许 SDK 内部主机暂存，不要求或宣称 GDR，也不包含 SSD 和性能收益验收。

## 配置

配置在服务启动时读取，修改后需要重启对应服务。P 和 D 使用相同源码、SDK、模型标识、KV 精度、目标 P 的 CP 布局和 instance salt。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `RTP_LLM_REMOTE_CACHE_ENABLE_DECODE_PUBLISH` | 关闭 | 只有精确值 `1` 开启；不设置或设为 `0` 关闭。 |
| `RTP_LLM_REMOTE_CACHE_DECODE_PENDING_MIB` | 原生池容量的 1/8，最多 4 GiB | D 尚不能释放的原生页预算，按唯一物理页计费。显式值须为正整数，不超过 16384 MiB，也不能超过实际原生池容量。 |
| `RTP_LLM_REMOTE_CACHE_DECODE_PENDING_JOBS` | `4` | D 未完成发布任务的预算；允许 `1` 到 `64`。 |

开启时还需启用现有缓存复用、远端缓存和 DRAM PACE 配置。关闭时不解析发布预算，不创建专属发布预算或资源 owner；P 不增加已计算边界字段，D 跳过新增边界校验。关闭态兼容性和开启态功能需要分别验证，未做性能对照不能据此宣称零性能开销。

## 支持范围和边界

- 支持 P 的 CP 切分和复制布局；D 使用 TP=1，DP 与 P 的 CP 数独立配置。
- 仅支持同步、非投机、单序列的正常完成路径；不从取消、错误或多序列请求猜测可发布的检查点。
- P 显式传递实际已计算 KV 的半开终点，D 校验成功加载的边界。最后一个采样 token 尚无目标 KV，不能计入已计算范围。
- D 按实际可用的 FULL、state/SWA 检查点对齐；尾部不足或所需状态已不在时退回可用检查点，不能把可变末状态标成较早状态。
- 恢复仍遵循模型原有的最小尾部补算规则。DSV4.1 的 `cache_min_replay_tokens=128`，还需按目标 CP 的复用单位对齐；已发布某个检查点不保证较短的下一轮请求会查找该检查点。验证 D 新增区间时必须保留真实历史 token IDs，并给下一轮输入留出所需的补算尾部。
- FULL 按目标 peer 选择完整原生页，包含需要的 scale；复制布局接收完整页。state/SWA 按既有 CP mapper 和实际 payload 布局投影。
- 预算不足时跳过可选发布，不影响已经生成的回答。进入异步队列不等于远端发布成功。

## 完成与异常

发布在请求释放原 KV 页前取得独立的页引用、描述符和预算；不增加应用层 CPU KV 快照。只有全部载荷成功、Manager 的 `FinishWrite` 确认成功后，日志才记录提交完成。

尚未提交、载荷完成、完成未知是不同状态。普通 SDK 错误码不构成缓冲区可释放的证明，Manager 提交确认也与载荷完成分开处理。完成未知时保留页、SDK 注册、描述符和预算，停止新的可选发布；没有传输排空证明时停机等待，不能强制回收后报告正常退出。

保留本地 session 描述符不等于为远端分配续租。原 SDK／现有 Manager 的永久超时排空及远端目标回收边界需要单独核实，不以“未主动 abort”或“析构已调用”代替证明。
