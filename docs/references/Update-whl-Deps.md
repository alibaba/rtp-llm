# Update whl Deps

To ensure that Python dependencies are correctly referenced by code and test cases, and properly resolved during packaging, the following three steps need to be completed:

- Declare the library and its version in `deps/deps.json`

- Regenerate the per-profile `requirements_lock` files with `scripts/rtpcli deps sync`

- Add the corresponding pip package dependencies to the py_library targets that use the relevant libraries in the Bazel BUILD file

## 1. Declare the dependency in `deps/deps.json`

`deps/deps.json` is the single source of truth for all Python dependencies. Add a package under `packages`:

- Common (all hardware): put it under the package's `common` block, e.g. `{"name": "transformers", "common": {"spec": "==4.46.2"}}`.
- Hardware-specific (torch, hardware compute libs, …): put it under `per_profile.<profile>`, e.g. `{"name": "flash-attn", "per_profile": {"cuda12_9": {"spec": "==2.8.3+..."}}}`.

A package that does not exist in every profile is recorded in `exceptions` (`exists_in` lists the profiles that have it; `allowed_refs` optionally restricts where it may be referenced). (The hand-written `requirements_*.txt` sources were retired in favour of the manifest; the relock composes its uv input in a temporary directory, so no requirements file is committed.)


## 2. Generate requirements_lock file

Lock files must not be manually modified and can only be automatically generated through relevant commands from the base dependency description files.

When opening any dependency file starting with requirements_lock, you will find the generator stamp at the top of the file:

```txt
# This file is autogenerated (uv, constraint-pinned relock). DO NOT EDIT.
# input-hash: <sha256 of the manifest-composed inputs>
```

Regenerate one profile (or all profiles) directly from the public checkout:

```bash
scripts/rtpcli deps sync --profile cuda12_9
scripts/rtpcli deps check --all
```

The relock is constraint-pinned: already-locked versions are frozen and only new or changed pins are resolved, against the per-flavor OSS index tree (`simple-<arch>/`) with the public mirror as fallback. Custom or hardware-specific wheels must be published to the declared OSS PEP 503 index first; direct wheel URLs are forbidden and rejected by the gate.

After editing `deps.json`, regenerate only the affected profiles, run `scripts/rtpcli deps check --all` — it must pass before committing.

**Important note**: If lock file conflicts occur during code merging, do not merge the conflicting content manually. Regenerate the affected lock with `scripts/rtpcli deps sync --profile <name>`.

## 3. Add the dependencies to the Bazel BUILD file


At this point, the dependencies can be installed correctly, but Python files still cannot properly reference these Python libraries. We also need to declare the dependencies in the Bazel BUILD files.


In the `rtp_llm/BUILD` file, locate the requirement() function and add the new dependency to its internal list to declare the existence of the dependency.

```bazel
requirement([
    "sentencepiece",
    "transformers",
    "pynvml",
    "tiktoken",
    # ...
    # add your new dependencies here
])
```

In the py_library targets that use the corresponding dependency libraries, add the declared dependencies, for example:

```bazel
py_library(
    name = "utils",
    srcs = glob([
        "utils/**/*.py",
    ]),
    data = [":cutlass_config"],
    deps = [
        ":torch",
        ":safetensors",
        ":lru-dict",
        ":cpm_kernels",
        ":prettytable",
        "//rtp_llm/aios/kmonitor:kmonitor_py",
    ] + arch_dep + internal_deps()
)
```

Wheel packaging metadata (`Requires-Dist`) is fully derived from `deps/deps.json` — do not hand-edit any `wheel_requires*.txt`:

- Common runtime packages: names come from the manifest `packages[].common` (minus `wheel.exclude`) plus the `wheel.groups.wheel` extras (names only, no versions); versions are taken from the lock.
- Architecture-specific big items (torch, flash-attn, …): add the package name to `wheel.arch_names.<profile>`; the version is derived from that profile's lock.
- Every entry in `wheel.exclude` must carry a machine-checkable form (`{"shipped": false, "reason": …}` or `{"provided_by": [<leaf files>]}`), enforced by `deps/check_manifest.py`.
- A package that only exists in some profiles must be registered in `deps.json`'s `exceptions` (`exists_in` + allowed reference sites), otherwise the gate fails.

After any of these changes, regenerate the affected locks and commit the generated files together with your change; `scripts/rtpcli deps check --all` verifies everything stays consistent.
