## MFU计算

解析有效FLOPs，乘加计2FLOPs；BF16峰值分母采用用户给定的2250 TFLOP/s。S=80960 patch，23段各3520 token，H=1152，I=4304，L=27，M=20240。FA4非causal，Q/K/V均72维。

| 部分 | FLOPs公式 | 每视频TFLOP |
| --- | --- | --- |
| Patch | 2×S×1536×H | 0.286513 |
| QKV+attention projection | L×8×S×H² | 23.207545 |
| MLP两次GEMM | L×4×S×H×I | 43.352984 |
| QKᵀ+PV | L×4×23×3520²×H | 35.455972 |
| Merger两次GEMM | 2×M×(4608²+4608×4096) | 1.623573 |
| 合计 |  | 103.926588 |

MFU = QPS × 103.926588 / 2250 × 100%。并发16：7.117403×103.926588/2250=32.87499%。

Norm、GELU、softmax、RoPE等逐元素运算未计入有效模型FLOPs，耗时保留在分母中；不把硬件内部padding的无效运算加进分子。MFU不等于nvidia-smi GPU utilization或Tensor Core pipeline活跃率。

## 结论与限制

- FA4为ViT内最大单项，约39.93/43.48ms每视频，占ViT kernel时间约33%；两次MLP GEMM合计27.62/29.49ms。
- GELU、LayerNorm、RoPE合计约33.84/36.26ms，不能按GEMM峰值算力解释这些算子。MFU还受这部分逐元素计算和内存访问耗时影响。
- 提高并发主要填补批次空档：无profiler的ViT GPU区间占窗口从约80%增至91%；同时每请求解码/预处理等待从202ms增至1174ms。等待与其他请求计算重叠，不能把1174ms全部当作可回收的吞吐损失。
- Batch上限16不代表实际batch16。中位轮平均实际batch约1.99/3.98；并发16中位轮最大实际batch12。这里测的是生产scheduler实际形成的混合batch。
- GPU copy时间远小于NVDEC调用墙钟。下一步需区分驱动同步、Python/CPU竞争和解码引擎，不能从copy数量推断带宽瓶颈。此次未采NCU硬件计数器，不作DRAM/occupancy/MTU饱和结论。
