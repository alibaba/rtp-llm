## 5. 模型 forward 和权重语义

### Target

Embedding 后，physical token 数必须能被 TP 整除；按 TP rank 切 token shard。Decoder 选择 KDA 或 MLA，MLP 选择 dense 或 latent MoE。Dense 权重在 SP 下复制、计算本 rank 的 token；不要恢复早期错误的额外 dense TP 分片。

AttnRes 使用 `attn_res_block_size=12` 和 residual bank，在相应层更新 anchor。最后一次 AttnRes 之后、final norm 之前的 hidden 是 MTP feature。Target 返回 `PyModelOutputs(self.norm(hidden), hidden)`：第一项给 logits 投影，第二项给 MTP。两个值不能用同一个旧 hidden 字段混用。

### Draft

`KimiK3MtpModel` 使用共享 embedding/head 和独立 draft norm。先把 token embedding 和 target/上一轮 recurrent hidden 分别归一化，经 `eh_proj` 合并，再走 nextn decoder。返回 final norm 后 logits input 和 norm 前 recurrent hidden。下一次预测复用同一 module 和 cache。模型必须拥有每个物理 token 的 position；position=0 的 embedding 屏蔽是模型语义，不能当冗余 kernel随意去掉。

### Loader

KDA 的 Q/K/V/G/F_a/beta 等融合布局与 TP 分片按分量语义定义，不能只按拼接矩阵等分。MLA 输入投影和 q_b/kv_b 各自维护应有布局；吸收矩阵保持 BF16。专家保留量化 bytes/scales，按 EP 分配。共享分支、latent norm/proj、AttnRes projection/norm 和 draft nextn 来源均需独立检查。

完整 target 的本地快照为 96 个 shard、497220 个 tensor；draft 为 9 个 shard、5404 个 tensor。原 draft index 的 `total_size` 包含 header 字节，任务 view 只修正 index 元数据并 hardlink 原 shard，不改原始 payload。加载后必须检查实际 FastSafetensors 日志，配置字符串不是 loader 执行证明。

## 6. 实际算子与 Graph 路径

### Prefill MLA

`KimiK3TokenspeedPrefill` 使用 `tokenspeed-mla==0.1.8`，`TOKENSPEED_MLA_PREFILL_BACKEND=cutedsl`，QK head dim 192、V dim 128。Q/K/V 都是 BF16；按实际 ragged indptr 规划，不是 FP8 KV 存储路径。V 从上投影 split 出来时可能是 strided，须提供 contiguous 输入，这一步对应原生实现的布局要求。

### Decode / target verify / draft update

`NativeMlaDecode` 用 vLLM stable-libtorch 的 `fused_kimi_k3_mla_decode_q_concat_kv_cache_insert`，在 RTP page table/slot mapping 上完成 absorbed Q 拼接和 cache insert。写入后沿 RTP CacheStore publication，再进行 attention。

当前实测 kernel page 是 **64**，`backend=trtllm-gen`；page128 分支选择 `cute-dsl`。都通过 FlashInfer API，不能写成“decode 已完全采用 TokenSpeed”。普通 logical block 为4096，与 kernel page64是不同概念。

Graph metadata 在 capture 前分配固定物理形状和最大 capacity。replay 更新有效行、block table、slot mapping。dummy page0映射为 slot=-1，防止覆盖真实 cache 或预留页。draft-update 按总 token bucket，其同一 bucket 的请求分布可变；capture 的 query bound 必须容纳后续 replay 的真实布局。`max_seq_len` 和 semaphore buffer 等资源在 capture 前确定，不能 replay 时重新分配。

### KDA/Conv/MoE

KDA runtime 选择 `KIMI_K3_KDA_PREFILL_BACKEND=vllm_triton`。vendored `vllm_kda/UPSTREAM.json` 记录来源及修改，状态仍接 RTP 候选 checkpoint/commit 机制，没有 replay 优化。

原生 DeepGEMM 以独立包 `k3_native_deep_gemm` 加载，而非替换全局 RTP DeepGEMM。固定 DeepGEMM commit `a6bbb8000161c0dc3a85a0300a905f76898a7913`，版本2.8.0；`BUILD_INFO.json` 校验 source、Graph patch、Torch版本。Graph epoch patch 防止 capture/replay 重复 gridid 破坏 SiTU combine readiness，不改变算术。

### MTP/异步准备问题

host rejection 会把 draft 输入压缩到实际接受长度。因此 `launchDraftPrefillPrepareAsync` 在非 DSpark、非 stream-async、非 device-state 模式下不再复用 rejection 前的 metadata，交给最终 compact 输入准备。DSpark/device-state 仍走原固定几何路径。这是公共执行器改动，已加对应测试，但仍需要最终旧模型回归。

## 7. SP、Cache 和 RDMA 不变量

- 仅 opt-in K3 使用新 SP padding；逻辑请求/token 和物理 padding 请求/token 分离。
- Prefill 按 token 对齐；draft/verify 按完整请求对齐，单位 `TP/gcd(TP,每请求 token 数)`。
- 所有 cache tag 的 metadata、position、hidden 和 token 同步补齐；虚拟行不进入真实输出和 PD publication。
- Target verify 接受之后按 row gather 取对应真实 hidden/logits；不要把 padding 行或未接受 candidate 当成下一步递推输入。
- KDA recurrent、conv、MLA KV 继续使用 main 的候选状态保存/选择机制；本次未整体覆盖 executor 或 Graph runner。
- 沿 main descriptor、CacheStore/RPC/完成回调传输，不复制 vLLM 的 N−1 PD 交接。
- 当前普通复用单位4096。禁止采用旧 PageRR `TP × block` 的复用断言。
- `GetWorkerStatus.precision` 当前可能返回硬编码 `FP16`（QuantMethod::None），它不是 tensor dtype 证据；看 all-rank loader、实际张量和算子配置。
