# Fixed vLLM four-layer 64K NIXL PD trace, 2026-09-29

This repeat used pinned vLLM `3df4ae153eb385e27b52f26c81f8edb9e20b9984` on L20-dev-111 (Prefill) and L20-dev-112 (Decode), TP8/EP8, the same four-layer checkpoint, TokenSpeed MLA, E4M3 KV cache and Prefill query, and PYNCCL. The target shards were read directly from 3FS in 13.77 and 15.16 seconds respectively. The NIXL toy proxy is the unmodified script from that vLLM revision, preserved beside the launch script in this handoff directory. vLLM had no Native MTP. Its checkpoint selected MXFP4 for routed MoE, so this is not an all-FP8-weight comparison with RTP.

The runner submitted 65,537 token IDs: the fixed RTP 65,536-token prefix plus one held-back copy of its last token. All eight rank traces contain three `execute_context_1(65536)_generation_0(0)` GPU annotations, proving Prefill computed the full fixed prefix. The original 64K prefix ID SHA256 is `97a53100491426d80436747b477dbe592ea1106eed6308a99ab83ba1bd3863ee`. Seventeen requests (14 warmups, three profiled) returned HTTP 200 with eight output tokens. The Decode NIXL metrics record 136 transfers, matching 17 requests across eight ranks, 5,506,080,768 bytes transferred and zero failed transfers. All eight Decode ranks logged a successful compatibility check.

The complete HTTP warmup time **did not converge** under the final-three ±5% rule, and `input.json` records this exception. The three profiled target GPU spans were 112.793, 111.386 and 111.276 ms (median **111.386 ms**, maximum deviation about 1.3%). `independent-response-trace-audit.json` verifies all saved response digests and token counts, the fixed-prefix and held-back-token hashes, all rank annotations, GPU span convergence, and the Decode NIXL transfer metrics. It passed, while recording three replacement characters in the random four-layer outputs; no answer-quality claim follows. vLLM did not echo the submitted token IDs in its responses, so the trace independently proves the Prefill length but the exact token values remain supported by the runner fixture and submission hashes. This is a warmed GPU target diagnostic with stable trace spans; it is not a converged complete HTTP benchmark. The corresponding four-layer integrated target trace measured 73.593 ms and the fixed `feat/k3_dev` target trace measured 71.556 ms, but their module dispatch and routed-MoE precision differ. The trace supports operator investigation, not an unconditional three-way winner claim.

`vllm-pd-3df4-r2-traces.tar.gz` contains all eight raw rank traces. `requests-64k-vllm-3df4-r2.tar.gz` contains every response, input metadata, runner output and exit code. `target-analysis.json` records the rank-level GPU scope and kernel-family summary. The logs and metrics files retain loader, PYNCCL, FP8 MLA and NIXL evidence. `archive.sha256` lists their digests. FlashInfer autotune was disabled because the fixed version's 64K startup tuning had previously exceeded five minutes; this remains a limitation of the vLLM comparison.
