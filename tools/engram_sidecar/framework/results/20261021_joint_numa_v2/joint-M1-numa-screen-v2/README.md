## Joint lookup and correctness boundary

Both layer lookups execute sequentially inside **one** per-path event/Graph
interval and return a tuple of actual BF16 outputs. This measures a real joint
lookup chain, not the sum of two P99 estimates. The layers use independent input
traces with seeds 20261122 and 20262422; eager/Graph hashes match for each layer.
The underlying traces are not exported/regenerated by this audit, so exact trace
bytes are supported by recorded hashes and the verified trace-generating source.

Source `415ef274e19e45f71e705802500ed5488a057289` verifies both layers' actual
outputs separately, for both local/remote paths, against independent checkpoint
FP8/E8M0-to-BF16 bit patterns. Recorded checks use changed random inputs 0 and 1
before timing, hot input 0 after its distribution, and random input 99 after its
distribution. Graph checks inspect actual replay outputs, not an eager overwrite.
These are four checkpoints per case, not correctness checks on every timed sample.

Excluded: n-gram hash/history, WKV/projection, gating/residual, real intervening
model work or dependencies, attention/MoE/EP traffic, scheduling and HTTP. Random
IDs are uniform across the actual tables; hot IDs are fixed. Neither is a real
production token distribution. No L2 disturbance was used. The event intervals
do not isolate fabric latency or exclusive kernel execution.

**The 188.833 GiB allocation is not this screen's active working set.** One
selected row has 256 weight bytes plus 8 scale bytes. For M=1, 24 heads, two
layers and 100 random samples, the logical accessed data is at most 1,267,200
bytes (about 1.21 MiB) per backend before duplicates and cache-line overfetch.
Both local and remote backings together are about 2.42 MiB by this calculation,
compared with runtime L2 of 135,528,448 bytes (129.25 MiB). Eager and Graph reuse
the same trace, including IDs previously used by warmup/correctness checks.
Uniform selection across the full tables does not prevent those rows remaining
cached. Cache hit rate was not measured: `cache_claim=uncontrolled` applies.
These timings cannot be described as the cost of cold remote memory or assumed
to include whole-model WKV/MoE/attention cache pressure. A future scratch
disturbance run will likewise not, by itself, establish guaranteed cold access.
